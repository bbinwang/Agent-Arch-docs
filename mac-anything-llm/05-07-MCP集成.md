## 1. 架构概述

AnythingLLM 实现了 **MCP（Model Context Protocol）** 客户端，可连接任意 MCP Server 并将其工具暴露给 Agent 使用。MCP 是 Anthropic 提出的开放协议，标准化了 LLM 应用与外部工具的集成方式。

### 1.1 核心组件

| 组件 | 文件 | 职责 |
|------|------|------|
| MCPHypervisor | `MCP/hypervisor/index.js` | MCP Server 生命周期管理（启动、停止、重载） |
| MCPCompatibilityLayer | `MCP/index.js` | 将 MCP 工具转换为 aibitat 插件 |
| MCP Server 配置 | `storage/plugins/anythingllm_mcp_servers.json` | MCP Server 定义持久化 |
| MCP 管理端点 | `endpoints/mcpServers.js` | MCP Server CRUD API |

### 1.2 支持的传输方式

| 传输方式 | 说明 | 使用场景 |
|---------|------|---------|
| `stdio` | 标准输入/输出 | 本地进程（如 `npx @modelcontextprotocol/server-filesystem`） |
| `sse` | Server-Sent Events | 远程 HTTP 服务 |
| `streamable-http` | 流式 HTTP | 新版 MCP HTTP 传输 |

## 2. MCPHypervisor — Server 生命周期管理

### 2.1 单例模式

```javascript
class MCPHypervisor {
  static _instance;
  mcps = {};  // 运行的 MCP Server 实例映射

  constructor() {
    if (MCPHypervisor._instance) return MCPHypervisor._instance;
    MCPHypervisor._instance = this;
    this.#setupConfigFile();
    return this;
  }
}
```

**设计模式**：单例模式。确保全局只有一个 Hypervisor 实例管理所有 MCP Server。

### 2.2 配置文件管理

```javascript
#setupConfigFile() {
  this.mcpServerJSONPath = path.resolve(
    process.env.STORAGE_DIR ?? path.resolve(__dirname, "../../../storage"),
    "plugins/anythingllm_mcp_servers.json"
  );

  if (!fs.existsSync(this.mcpServerJSONPath)) {
    fs.mkdirSync(path.dirname(this.mcpServerJSONPath), { recursive: true });
    fs.writeFileSync(this.mcpServerJSONPath,
      JSON.stringify({ mcpServers: {} }, null, 2));
  }
}
```

**配置文件格式**：
```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "env": {}
    },
    "my-api": {
      "url": "https://api.example.com/mcp",
      "transport": "streamable-http"
    }
  }
}
```

### 2.3 Server 启动流程

```javascript
async bootMCPServers() {
  const configs = this.mcpServerConfigs;

  for (const { name, server } of configs) {
    if (this.mcps[name]) continue; // 已启动

    try {
      const client = new Client({ name: "anythingllm", version: "1.0.0" });

      // 根据配置选择传输方式
      let transport;
      if (server.command) {
        // stdio 传输
        transport = new StdioClientTransport({
          command: server.command,
          args: server.args,
          env: { ...process.env, ...server.env },
        });
      } else if (server.url) {
        // HTTP 传输
        transport = server.transport === "sse"
          ? new SSEClientTransport(new URL(server.url))
          : new StreamableHTTPClientTransport(new URL(server.url));
      }

      await client.connect(transport);
      this.mcps[name] = client;
      this.mcpLoadingResults[name] = { status: "success", message: "" };
    } catch (error) {
      this.mcpLoadingResults[name] = { status: "failed", message: error.message };
    }
  }
}
```

**关键设计**：
- **环境变量继承**：`env: { ...process.env, ...server.env }` 确保子进程可访问必要环境变量。
- **错误隔离**：单个 Server 启动失败不影响其他 Server。

## 3. MCPCompatibilityLayer — 工具转换

### 3.1 功能

`MCPCompatibilityLayer` 继承 `MCPHypervisor`，负责将 MCP Server 的工具转换为 aibitat 插件格式。

### 3.2 核心方法

```javascript
async convertServerToolsToPlugins(name, _aibitat = null) {
  const mcp = this.mcps[name];
  if (!mcp) return null;

  // 1. 列出 MCP Server 的所有工具
  const response = await mcp.listTools();
  let tools = response.tools;

  // 2. 过滤被抑制的工具
  const suppressedTools = this.getSuppressedTools(name);
  tools = tools.filter((tool) => !suppressedTools.includes(tool.name));

  // 3. 转换为 aibitat 插件格式
  const plugins = [];
  for (const tool of tools) {
    plugins.push({
      name: `${name}-${tool.name}`,
      description: tool.description,
      plugin: function () {
        return {
          name: `${name}-${tool.name}`,
          parameters: { $schema: "...", ...tool.inputSchema },
          handler: async function (args = {}) {
            const result = await currentMcp.callTool({
              name: tool.name,
              arguments: args,
            });
            return result;
          },
        };
      },
    });
  }
  return plugins;
}
```

**设计要点**：
- **命名空间隔离**：工具名格式为 `{serverName}-{toolName}`，避免不同 Server 的工具名冲突。
- **Schema 透传**：MCP 工具的 `inputSchema` 直接透传给 aibitat，保持类型信息。
- **工具抑制**：管理员可配置 `suppressedTools` 禁用特定工具。

### 3.3 活动 Server 列表

```javascript
async activeMCPServers() {
  await this.bootMCPServers();
  return Object.keys(this.mcps).flatMap((name) => `@@mcp_${name}`);
}
```

**`@@mcp_` 前缀**：前端通过该前缀识别 MCP 工具，提供特殊 UI 展示。

## 4. 安全注意事项

> **⚠️ 警告**：MCP 本质上是 **任意代码执行**。AnythingLLM 的注释明确指出：
> 
> *"It is the user responsibility for the MCP server definitions to be correct and also functioning tools depending on their deployment (docker vs local) as well as the security of said tools since MCP is basically arbitrary code execution."*

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 恶意 MCP Server | 可执行任意命令 | 仅使用可信来源的 Server |
| 环境变量泄露 | 子进程继承 `process.env` | 白名单过滤敏感变量 |
| 文件系统访问 | 可读写服务器文件 | 限制 Server 工作目录 |
| 网络访问 | 可发起任意 HTTP 请求 | 网络隔离（Docker 网络策略） |

## 5. 潜在问题与改进建议

| 问题 | 影响 | 建议 |
|------|------|------|
| 无 MCP Server 健康检查 | 故障 Server 仍被调用 | 添加定期 `ping` 检查 |
| 无工具调用超时 | 卡死导致 Agent 挂起 | 为 `callTool` 添加超时 |
| 配置热更新不支持 | 修改配置需重启 | 监听文件变化自动重载 |
| 无调用日志审计 | 无法追踪工具调用 | 记录每次 MCP 调用到 `event_logs` |
