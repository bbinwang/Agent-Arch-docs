## 1. ADR-001：选择 Prisma + SQLite 作为默认数据层

### 状态：已接受

### 上下文

AnythingLLM 需要选择一个 ORM 和默认数据库。选项包括：
- **Prisma + SQLite**：零配置、嵌入式、适合自托管
- **Prisma + PostgreSQL**：生产级、需独立服务
- **TypeORM + MySQL**：传统方案
- **MongoDB + Mongoose**：文档数据库

### 决策

选择 **Prisma + SQLite** 作为默认配置，同时支持切换到 PostgreSQL。

### 理由

| 因素 | Prisma + SQLite | Prisma + PostgreSQL |
|------|-----------------|---------------------|
| 部署复杂度 | ⭐ 零配置 | ⭐⭐⭐ 需独立服务 |
| 自托管友好 | ⭐⭐⭐ 嵌入式 | ⭐⭐ 需管理 PG |
| 性能（单写） | ⭐⭐⭐ 足够 | ⭐⭐⭐ 足够 |
| 性能（并发写） | ⭐ 单写限制 | ⭐⭐⭐ 高并发 |
| 迁移能力 | ⭐⭐⭐ Prisma Migrate | ⭐⭐⭐ Prisma Migrate |
| 类型安全 | ⭐⭐⭐ 自动生成 | ⭐⭐⭐ 自动生成 |

### 后果

- **正面**：用户无需配置数据库即可开始使用，降低入门门槛。
- **负面**：高并发写入场景下 SQLite 可能成为瓶颈，需切换到 PostgreSQL。
- **缓解**：Schema 设计兼容两者，切换只需修改数据源配置。

## 2. ADR-002：自研 aibitat Agent 框架而非集成 LangChain Agent

### 状态：已接受

### 上下文

Agent 框架选项：
- **LangChain Agent**：成熟、功能丰富、但灵活性受限
- **AutoGPT/AutoGen**：特定场景优化
- **自研 aibitat**：完全可控、深度集成

### 决策

自研 **aibitat** 框架。

### 理由

1. **深度集成**：aibitat 与 AnythingLLM 的 Provider 插件体系无缝集成，所有 40+ LLM Provider 可直接用于 Agent。
2. **WebSocket 原生支持**：实时双向通信是核心需求，自研框架可原生支持。
3. **工具智能选择**：独创的 router-classifier 插件，减少 80% Token 消耗。
4. **插件热插拔**：20+ 工具插件可独立开发、测试、部署。
5. **无外部依赖风险**：避免 LangChain 频繁 API 变更带来的维护成本。

### 后果

- **正面**：完全可控、深度定制、性能优化空间大。
- **负面**：需自行维护框架、社区生态不如 LangChain。

## 3. ADR-003：Collector 作为独立进程而非进程内模块

### 状态：已接受

### 上下文

文档处理（OCR、Puppeteer、大文件解析）是 CPU 密集操作。选项：
- **进程内模块**：简单、但阻塞事件循环
- **独立进程**：隔离、可独立扩展
- **Serverless 函数**：弹性、但冷启动延迟

### 决策

Collector 作为 **独立 Node.js 进程**，通过内部 HTTP 通信。

### 理由

1. **故障隔离**：Collector 崩溃不影响 API Server。
2. **资源隔离**：CPU 密集操作不阻塞 I/O 事件循环。
3. **独立扩展**：可部署多个 Collector 实例分担负载。
4. **语言无关性**：HTTP 接口允许未来用其他语言重写。

### 后果

- **正面**：架构清晰、可独立扩展。
- **负面**：增加部署复杂度（需管理多个进程）。

## 4. ADR-004：Provider 插件化架构

### 状态：已接受

### 上下文

需要支持 40+ LLM Provider、12 种 Embedding 引擎、10+ 向量数据库。

### 决策

采用 **插件化架构**，每个 Provider 是独立目录，实现统一接口，通过注册表动态加载。

### 理由

1. **开闭原则**：新增 Provider 无需修改现有代码。
2. **单一职责**：每个 Provider 封装自己的 API 细节。
3. **可测试性**：可 mock 任意 Provider 进行单元测试。
4. **社区贡献**：开发者可独立贡献新 Provider。

### 接口契约示例

```javascript
// 所有 LLM Provider 需实现
class BaseLLMProvider {
  constructor(embedder, modelPreference) {}
  async getChatCompletion(messages, options) {}
  async streamGetChatCompletion(messages, options) {}
  async getEmbedding(text) {}
  promptWindowLimit() {}
  streamingEnabled() {}
}
```

## 5. ADR-005：SSE 而非 WebSocket 用于聊天流式响应

### 状态：已接受

### 上下文

聊天流式响应选项：
- **SSE (Server-Sent Events)**：单向、HTTP 兼容、自动重连
- **WebSocket**：双向、需额外协议
- **HTTP Long Polling**：兼容性最好、效率最低

### 决策

聊天流式响应使用 **SSE**，Agent 实时通信使用 **WebSocket**。

### 理由

| 因素 | SSE | WebSocket |
|------|-----|-----------|
| 单向推送 | ✅ 适合聊天 | ❌ 过度设计 |
| HTTP 兼容 | ✅ 无需额外端口 | ❌ 需 ws:// 协议 |
| 自动重连 | ✅ 浏览器原生支持 | ❌ 需手动实现 |
| 代理友好 | ✅ 标准 HTTP | ❌ 部分代理不支持 |
| 双向通信 | ❌ 不支持 | ✅ Agent 需要 |

### 后果

- 聊天场景使用 SSE，简单可靠。
- Agent 场景使用 WebSocket，支持双向实时通信。

## 6. ADR-006：Vite 而非 Next.js 作为前端构建工具

### 状态：已接受

### 上下文

前端框架选项：
- **Next.js**：SSR、SSG、全栈能力
- **Vite + React**：SPA、快速 HMR、轻量
- **Remix**：嵌套路由、表单处理

### 决策

选择 **Vite + React**（纯 SPA）。

### 理由

1. **AnythingLLM 是 SPA**：无 SSR 需求（除嵌入 Widget 外）。
2. **快速 HMR**：Vite 的开发体验优于 Next.js。
3. **构建产物小**：无需 SSR 运行时，Docker 镜像更小。
4. **部署简单**：静态资源可直接由 Nginx 或 CDN 提供。
5. **嵌入友好**：构建后的 JS/CSS 可直接嵌入第三方网站。

### 后果

- **正面**：开发体验好、构建快、部署简单。
- **负面**：无 SSR，SEO 不友好（但 AnythingLLM 是工具型应用，SEO 不重要）。

## 7. ADR-007：AES-256-GCM 端到端加密

### 状态：已接受

### 上下文

敏感数据（API Key、MCP 凭证、邀请码）需要加密存储。

### 决策

使用 **AES-256-GCM** 算法进行端到端加密。

### 理由

1. **认证加密**：GCM 模式提供加密 + 完整性校验，防止篡改。
2. **标准算法**：AES-256 是 NIST 标准，安全可靠。
3. **性能**：硬件加速（AES-NI）下性能优秀。
4. **密钥管理**：使用 `comKey`（Communication Key）作为密钥派生源。

### 实现

```javascript
// server/utils/EncryptionManager/index.js
const crypto = require("crypto");

class EncryptionManager {
  constructor() {
    this.algorithm = "aes-256-gcm";
    this.key = this.#deriveKey();
  }

  encrypt(plaintext) {
    const iv = crypto.randomBytes(16);
    const cipher = crypto.createCipheriv(this.algorithm, this.key, iv);
    const encrypted = Buffer.concat([cipher.update(plaintext), cipher.final()]);
    const authTag = cipher.getAuthTag();
    return `${iv.toString("hex")}:${authTag.toString("hex")}:${encrypted.toString("hex")}`;
  }

  decrypt(ciphertext) {
    const [ivHex, authTagHex, encryptedHex] = ciphertext.split(":");
    const decipher = crypto.createDecipheriv(
      this.algorithm,
      this.key,
      Buffer.from(ivHex, "hex")
    );
    decipher.setAuthTag(Buffer.from(authTagHex, "hex"));
    return Buffer.concat([
      decipher.update(Buffer.from(encryptedHex, "hex")),
      decipher.final(),
    ]).toString();
  }
}
```

## 8. ADR-008：模型路由规则存储在关系数据库而非配置文件

### 状态：已接受

### 上下文

模型路由规则需要持久化。选项：
- **关系数据库**（model_routers + model_router_rules 表）
- **JSON 配置文件**
- **环境变量**

### 决策

使用 **关系数据库** 存储路由规则。

### 理由

1. **多用户支持**：不同管理员可创建自己的路由器。
2. **事务性**：规则创建/更新/删除支持事务。
3. **查询能力**：可按优先级、启用状态等条件查询。
4. **API 管理**：可通过 REST API 动态管理。

### 后果

- **正面**：灵活、可动态管理。
- **负面**：规则匹配需要查询数据库，需优化索引。
