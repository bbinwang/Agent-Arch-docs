## 1. 向量相似度检索

### 1.1 算法描述

向量检索是 RAG 管线的核心，用于在向量数据库中查找与用户问题最相似的文档块。

### 1.2 伪代码

```pseudocode
function similaritySearch(queryVector, topN, threshold):
    // 1. 在向量库中执行最近邻搜索
    candidates = vectorDB.annSearch(queryVector, topN * 2)  // 多取一些用于过滤
    
    // 2. 计算余弦相似度
    results = []
    for candidate in candidates:
        score = cosineSimilarity(queryVector, candidate.vector)
        if score >= threshold:
            results.append({ content: candidate.content, score: score })
    
    // 3. 按分数降序排序
    results.sort(by: score, order: desc)
    
    // 4. 返回 Top-N
    return results[0:topN]

function cosineSimilarity(vecA, vecB):
    dotProduct = sum(vecA[i] * vecB[i] for i in range(len(vecA)))
    magnitudeA = sqrt(sum(vecA[i]^2 for i in range(len(vecA))))
    magnitudeB = sqrt(sum(vecB[i]^2 for i in range(len(vecB))))
    return dotProduct / (magnitudeA * magnitudeB)
```

### 1.3 复杂度分析

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 暴力搜索（线性） | O(n × d) | O(n × d) |
| HNSW 索引（LanceDB 默认） | O(log n × d) | O(n × d) |
| IVF 索引（Milvus） | O(√n × d) | O(n × d) |
| 余弦相似度计算 | O(d) | O(1) |

> n = 向量数量，d = 向量维度（通常 768 或 1536）

### 1.4 优化建议

1. **使用 HNSW 索引**：LanceDB 默认使用 HNSW，查询复杂度 O(log n)。
2. **降维**：对高维向量使用 PCA 降维（牺牲少量精度换取速度）。
3. **量化**：使用 PQ（Product Quantization）减少内存占用。
4. **缓存**：对高频查询结果缓存。

## 2. 文本分块（Text Splitting）

### 2.1 算法描述

将长文本分割为适合嵌入模型的小块，保持语义完整性。

### 2.2 伪代码（递归字符分块）

```pseudocode
function recursiveCharSplit(text, chunkSize, overlap, separators):
    // 1. 选择分隔符（按优先级）
    separator = findFirstSeparator(text, separators)
    
    if separator is null:
        // 无分隔符，按字符硬切
        return hardSplit(text, chunkSize)
    
    // 2. 按分隔符分割
    chunks = text.split(separator)
    
    // 3. 合并小块
    result = []
    currentChunk = ""
    for chunk in chunks:
        if length(currentChunk + chunk) <= chunkSize:
            currentChunk += chunk + separator
        else:
            if currentChunk is not empty:
                result.append(currentChunk)
                // 保留重叠部分
                currentChunk = currentChunk[-overlap:] + chunk + separator
            else:
                // 单个块超过 chunkSize，递归分割
                subChunks = recursiveCharSplit(chunk, chunkSize, overlap, separators[1:])
                result.extend(subChunks)
    
    if currentChunk is not empty:
        result.append(currentChunk)
    
    return result

// 默认分隔符优先级
separators = ["\n\n", "\n", ". ", " ", ""]
```

### 2.3 复杂度分析

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 单次分割 | O(n) | O(n) |
| 递归分割（最坏） | O(n × k) | O(n × k) |

> n = 文本长度，k = 分隔符层级数

### 2.4 优化建议

1. **语义分块**：使用嵌入模型检测语义边界，而非固定长度。
2. **滑动窗口**：使用滑动窗口生成重叠块，提高检索召回率。
3. **并行分块**：对大文档并行处理各段落。

## 3. 记忆提取（两阶段管线）

### 3.1 算法描述

自动从聊天历史中提取关键事实，分为 Observer（观察者）和 Reflector（反思者）两阶段。

### 3.2 伪代码

```pseudocode
// Phase 1: Observer - 提取候选事实
function observerPhase(chats):
    candidateFacts = []
    for chat in chats:
        // 使用 LLM 提取事实
        prompt = buildObserverPrompt(chat)
        facts = llm.complete(prompt)
        candidateFacts.extend(parseFacts(facts))
    return candidateFacts

// Phase 2: Reflector - 分类、去重、过滤
function reflectorPhase(candidateFacts, existingMemories):
    operations = []
    for fact in candidateFacts:
        // 1. 分类作用域
        scope = classifyScope(fact)  // "global" or "workspace"
        
        // 2. 去重
        duplicate = findDuplicate(fact, existingMemories)
        if duplicate:
            // 更新现有记忆
            operations.append({ type: "update", id: duplicate.id, content: fact.content })
        else:
            // 新增记忆
            operations.append({ type: "create", scope: scope, content: fact.content })
    
    // 3. 过滤低质量
    operations = filterLowQuality(operations)
    
    return operations

// 主流程
function extractMemories(chats, existingMemories):
    candidates = observerPhase(chats)
    operations = reflectorPhase(candidates, existingMemories)
    applyOperations(operations)
```

### 3.3 复杂度分析

| 阶段 | 时间复杂度 | 说明 |
|------|-----------|------|
| Observer | O(n × LLM) | n = 聊天数，LLM = 单次 LLM 调用 |
| 去重 | O(m × k) | m = 候选事实数，k = 现有记忆数 |
| Reflector | O(m × LLM) | 单次 LLM 调用处理所有候选 |

### 3.4 优化建议

1. **批量处理**：将多轮聊天合并为一次 LLM 调用。
2. **增量去重**：使用向量相似度检测重复，而非精确匹配。
3. **异步执行**：记忆提取在后台 job 执行，不阻塞聊天。

## 4. 模型路由规则匹配

### 4.1 算法描述

根据用户消息、用户角色、时间窗口等条件，匹配最优的 LLM Provider。

### 4.2 伪代码

```pseudocode
function resolveRoute(workspace, message, user):
    // 1. 检查粘性会话
    sticky = getStickySession(workspace.id, user.id)
    if sticky and not isExpired(sticky, cooldown):
        return sticky.provider
    
    // 2. 加载规则（按优先级排序）
    rules = loadRules(workspace.router_id, orderBy: priority)
    
    // 3. 遍历规则
    for rule in rules:
        if not rule.enabled: continue
        
        if matchRule(rule, message, user):
            // 检查 Provider 可用性
            if isProviderAvailable(rule.target_provider):
                updateStickySession(workspace.id, user.id, rule)
                return { provider: rule.target_provider, model: rule.target_model }
    
    // 4. 无匹配，使用回退
    return { provider: fallback_provider, model: fallback_model }

function matchRule(rule, message, user):
    switch rule.type:
        case "keyword":
            return any(keyword in message for keyword in rule.keywords)
        case "token_budget":
            estimatedTokens = estimateTokens(message)
            return estimatedTokens > rule.threshold
        case "role":
            return user.role in rule.allowed_roles
        case "time_window":
            return isWithinTimeWindow(rule.start_time, rule.end_time)
        case "calculated":
            return evaluateConditions(rule.conditions, rule.condition_logic, message, user)
        case "llm":
            return llmClassify(rule.prompt, message)
```

### 4.3 复杂度分析

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 规则匹配（最坏） | O(r × c) | r = 规则数，c = 条件数 |
| 粘性会话检查 | O(1) | 内存 Map 查找 |
| LLM 分类 | O(LLM) | 单次 LLM 调用 |

### 4.4 优化建议

1. **规则索引**：对 keyword 类型规则建立倒排索引。
2. **缓存结果**：对相同消息缓存路由结果。
3. **短路求值**：AND 条件遇到 false 立即停止。

## 5. ReAct Agent 循环

### 5.1 算法描述

Agent 通过「思考 → 行动 → 观察」循环完成任务。

### 5.2 伪代码

```pseudocode
function reactLoop(agent, maxRounds, maxToolCalls):
    round = 0
    toolCallCount = 0
    
    while round < maxRounds:
        round++
        
        // 1. 调用 LLM 获取下一步行动
        response = llm.complete(
            systemPrompt = agent.systemPrompt,
            messages = agent.chatHistory,
            tools = agent.getToolDefinitions()
        )
        
        // 2. 解析响应
        if not response.hasToolCalls:
            // 无工具调用 → 最终回答
            return { type: "final", content: response.content }
        
        // 3. 执行工具调用
        for toolCall in response.toolCalls:
            if toolCallCount >= maxToolCalls:
                return { type: "limit_reached", content: "达到工具调用上限" }
            
            toolCallCount++
            
            // 查找工具
            plugin = agent.getPlugin(toolCall.name)
            if not plugin:
                agent.addMessage(role: "tool", content: "Unknown tool")
                continue
            
            // 执行工具
            result = plugin.call(toolCall.params)
            
            // 将结果加入历史
            agent.addMessage(role: "tool", content: result)
            
            // 推送事件
            emit("toolResult", { name: toolCall.name, result: result })
    
    return { type: "max_rounds", content: "达到最大循环轮次" }
```

### 5.3 复杂度分析

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 单次循环 | O(LLM + T) | LLM = LLM 调用，T = 工具执行 |
| 完整循环 | O(R × (LLM + T)) | R = 循环轮次 |
| 工具查找 | O(1) | HashMap 查找 |

### 5.4 优化建议

1. **并行工具调用**：无依赖的工具并行执行。
2. **工具结果缓存**：相同参数的工具调用缓存结果。
3. **提前终止**：检测到循环模式时强制终止。
