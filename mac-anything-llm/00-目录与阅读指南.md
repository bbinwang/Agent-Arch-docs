## 一、文档定位与目标读者

本文档是对 **AnythingLLM** 开源项目的全方位技术解剖。AnythingLLM 是一款自托管、多用户、支持多模型与多向量库的私有文档对话与 AI Agent 平台，采用 MIT 协议，当前版本 v1.15.0。

本文档面向以下四类读者，不同角色可按需选择阅读路径：

| 读者角色 | 关注重点 | 推荐章节 |
|---------|---------|---------|
| **系统架构师** | 整体架构、C4 模型、模块边界、部署拓扑 | 第 1、2、4、8、9 章 |
| **后端开发者** | API 设计、数据模型、Provider 插件、Agent 系统 | 第 5、6、7、10.1、10.2 章 |
| **前端开发者** | React 架构、聊天 UI、状态管理、国际化 | 第 5.9、5.10、10.1 章 |
| **运维 / DevOps** | 部署、Docker/K8s、CI/CD、监控、备份 | 第 8、10.1 章 |

## 四、术语表与缩写对照

| 缩写 / 术语 | 全称 | 含义 |
|------------|------|------|
| LLM | Large Language Model | 大语言模型 |
| RAG | Retrieval-Augmented Generation | 检索增强生成，AnythingLLM 的核心聊天模式 |
| VDB / Vector DB | Vector Database | 向量数据库，用于存储文档嵌入并提供语义检索 |
| Embedding | — | 文本的高维向量表示，AnythingLLM 支持 12 种 Embedding 引擎 |
| Workspace | — | 工作空间，AnythingLLM 的多租户隔离单元 |
| Agent | — | AI Agent，基于自研 aibitat 框架的函数调用循环 |
| MCP | Model Context Protocol | Anthropic 提出的模型上下文协议，AnythingLLM 已实现兼容 |
| SSE | Server-Sent Events | 服务器推送事件，用于聊天流式响应 |
| Collector | — | 文档采集与处理子服务（独立 Node 进程） |
| reranker | — | 重排序器，对向量检索结果进行二次精排 |
| hotdir | — | 热目录监听，自动导入指定目录下的新文档 |
| ADR | Architecture Decision Record | 架构决策记录 |
| C4 | Context/Container/Component/Code | 软件架构描述模型 |
| slug | — | URL 友好的唯一标识符（如工作空间 slug） |
| pfp | Profile Picture | 用户/工作空间头像 |
| comKey | Communication Key | 服务间通信签名密钥 |
| hypervisor | — | MCP Server 的管理调度器 |

## 五、关键项目路径速查表

为便于在阅读文档时定位源码，以下列出 AnythingLLM 的核心目录约定：

| 路径 | 职责 |
|------|------|
| `server/` | 后端 API 服务（Express，端口 3001） |
| `server/index.js` | 后端入口，注册中间件、路由、WebSocket |
| `server/endpoints/` | REST 端点（按业务域划分） |
| `server/models/` | Prisma 数据模型封装（业务逻辑层） |
| `server/utils/` | 工具库（AI Provider、向量库、Agent、MCP 等） |
| `server/prisma/schema.prisma` | 数据库 Schema（487 行，约 35 个模型） |
| `server/swagger/` | Swagger/OpenAPI 自动生成 |
| `server/jobs/` | 后台定时任务（嵌入、记忆提取、文档同步等） |
| `server/storage/` | 持久化存储根目录（SQLite、文档、模型、向量缓存） |
| `frontend/` | 前端 SPA（React + Vite） |
| `frontend/src/pages/` | 页面级组件（Login、Main、WorkspaceChat、Admin 等） |
| `frontend/src/components/` | 通用组件（30+ 个） |
| `frontend/src/hooks/` | 自定义 React Hooks（25 个） |
| `frontend/src/models/` | 前端 API 客户端封装 |
| `frontend/src/locales/` | i18n 国际化文件（30+ 语言） |
| `collector/` | 文档采集子服务（独立 Node 进程） |
| `collector/processSingleFile/` | 单文件处理管线（PDF/DOCX/XLSX/HTML 等） |
| `collector/processLink/` | 网页链接处理（Puppeteer 爬取 + 解析） |
| `collector/processRawText/` | 原始文本处理 |
| `collector/utils/` | 采集器工具（OCR、Whisper、加密、分词等） |
| `docker/` | Docker 构建与部署配置 |
| `cloud-deployments/` | 多云部署模板（AWS/GCP/DO/Helm/K8s/OpenShift/HF） |
| `open-computer/` | Open Computer 子项目（AI Agent 计算机环境） |
| `browser-extension/` | 浏览器扩展 |
| `embed/` | 可嵌入聊天组件 |
| `extras/` | 辅助脚本（翻译、公告、支持工具） |
| `.github/workflows/` | CI/CD 工作流（8 个） |

## 六、文档写作约定

1. **路径表示法**: 所有文件路径均相对于项目根目录（`anything-llm/`），例如 `server/index.js` 代表 `anything-llm/server/index.js`。
2. **代码引用格式**: 引用代码时使用 `` `函数名()` `` 或 `` `ClassName.method()` `` 内联格式；关键逻辑使用代码块并标注所在文件。
3. **Mermaid 图表**: 所有图表使用标准 ```mermaid 代码块，确保可在 GitHub / GitLab / Mermaid Live 中直接渲染。
4. **交叉引用**: 章节间使用相对路径 Markdown 链接，例如 `[聊天引擎](../05-05-聊天引擎与RAG管线.md)`。
5. **待确认标注**: 对于基于代码推断但未经官方确认的内容，使用 `> ⚠️ 需进一步确认` 引用块标注。
