## 1. 认证体系架构

AnythingLLM 支持两种认证模式，由 `MULTI_USER_MODE` 环境变量控制：

| 模式 | 认证方式 | 适用场景 |
|------|---------|---------|
| **单用户模式**（默认） | AUTH_TOKEN 环境变量 / JWT | 个人使用、桌面应用 |
| **多用户模式** | Session Cookie + bcrypt | 团队使用、Docker 部署 |

## 2. validatedRequest 中间件

### 2.1 功能

`server/utils/middleware/validatedRequest.js` 是所有受保护路由的第一道防线，负责：
1. 检测当前运行模式（单用户/多用户）
2. 验证请求凭据（AUTH_TOKEN 或 Session）
3. 注入 `response.locals.multiUserMode`

### 2.2 单用户模式认证流程

```javascript
async function validatedRequest(request, response, next) {
  const multiUserMode = await SystemSettings.isMultiUserMode();
  response.locals.multiUserMode = multiUserMode;
  if (multiUserMode)
    return await validateMultiUserRequest(request, response, next);

  // 开发模式或无 AUTH_TOKEN 时放行
  if (
    process.env.NODE_ENV === "development" ||
    !process.env.AUTH_TOKEN ||
    !process.env.JWT_SECRET
  ) {
    UserMetaCache.setFromRequest(request);
    next();
    return;
  }

  // 验证 AUTH_TOKEN
  const auth = request.header("Authorization");
  const token = auth ? auth.split(" ")[1] : null;
  if (!token) { /* 401 */ return; }

  const bcrypt = require("bcryptjs");
  const { p } = decodeJWT(token);

  // 验证 token 格式
  if (p === null || !/\w{32}:\w{32}/.test(p)) { /* 401 */ return; }

  // 验证 token 内容（bcrypt 比对）
  if (!bcrypt.compareSync(
    EncryptionMgr.decrypt(p),
    bcrypt.hashSync(process.env.AUTH_TOKEN, 10)
  )) { /* 401 */ return; }

  UserMetaCache.setFromRequest(request);
  next();
}
```

**认证逻辑详解**：

1. **JWT 解码**：`decodeJWT(token)` 解析 Bearer <REDACTED>，提取 `p` 字段（密码哈希）。
2. **格式校验**：`/\w{32}:\w{32}/` 确保 `p` 是 `hash:salt` 格式。
3. **内容校验**：使用 `bcrypt.compareSync` 比对解密后的 `p` 与 `AUTH_TOKEN` 的哈希。

**安全设计**：
- JWT 中的 `p` 字段经过 `EncryptionMgr` 加密，避免明文存储密码哈希。
- 使用 `bcrypt.hashSync(process.env.AUTH_TOKEN, 10)` 每次重新计算哈希，而非存储静态哈希。

**潜在问题**：
- `bcrypt.hashSync` 在每次请求时重新计算，存在性能开销（bcrypt 设计为慢哈希）。
- 开发模式完全放行，若生产环境误设 `NODE_ENV=development` 会导致认证绕过。

### 2.3 多用户模式认证流程

```javascript
async function validateMultiUserRequest(request, response, next) {
  const auth = request.header("Authorization");
  const token = auth ? auth.split(" ")[1] : null;
  if (!token) { /* 401 */ return; }

  // 尝试 API Key 认证
  const apiKey = await ApiKey.byToken(token);
  if (apiKey) {
    response.locals.user = await User.get({ id: apiKey.createdBy });
    return next();
  }

  // 尝试 Session 认证
  const user = await userFromSession(request, response);
  if (user) {
    response.locals.user = user;
    return next();
  }

  // 尝试 JWT 认证（临时 Auth Token）
  const tempToken = await TemporaryAuthToken.byToken(token);
  if (tempToken) {
    response.locals.user = await User.get({ id: tempToken.userId });
    return next();
  }

  response.status(401).json({ error: "Unauthorized" });
}
```

**多认证源支持**（按优先级）：
1. **API Key**：`api_keys` 表中的 `secret` 字段匹配。
2. **Session Cookie**：Express Session 中的 `userId`。
3. **临时 Auth Token**：`temporary_auth_tokens` 表（用于短期授权链接）。

## 3. 角色权限中间件

### 3.1 flexUserRoleValid

```javascript
function flexUserRoleValid(allowedRoles = DEFAULT_ROLES) {
  return async (request, response, next) => {
    // 允许所有角色时直接放行
    if (allowedRoles.includes(ROLES.all)) { next(); return; }

    // 非多用户模式放行
    const multiUserMode = response.locals?.multiUserMode ?? 
      (await SystemSettings.isMultiUserMode());
    if (!multiUserMode) { next(); return; }

    // 检查用户角色
    const user = response.locals?.user ?? 
      (await userFromSession(request, response));
    if (allowedRoles.includes(user?.role)) { next(); return; }

    return response.sendStatus(401).end();
  };
}
```

**设计特点**：
- **弹性权限**：非多用户模式下自动放行，使同一路径兼容两种模式。
- **角色常量**：`ROLES = { all: "<all>", admin: "admin", manager: "manager", default: "default" }`。

### 3.2 strictMultiUserRoleValid

与 `flexUserRoleValid` 类似，但在非多用户模式下返回 401（严格模式）。适用于仅多用户模式应访问的端点。

### 3.3 isSingleUserMode

```javascript
async function isSingleUserMode(_request, response, next) {
  const multiUserMode = await SystemSettings.isMultiUserMode();
  if (multiUserMode) return response.sendStatus(401).end();
  next();
}
```

**用途**：限制仅单用户模式可访问的端点（如单用户模式的设置页面）。

## 4. User 模型

### 4.1 核心方法

| 方法 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `User.create()` | 创建用户 | `{username, password, role, dailyMessageLimit, bio}` | `{user, error}` |
| `User.authenticate()` | 验证登录凭据 | `{username, password}` | `{user, error}` |
| `User.get()` | 查询单个用户 | `{id}` 或 `{username}` | `user` 或 `null` |
| `User.where()` | 查询多个用户 | `clause, limit, orderBy` | `users[]` |
| `User.update()` | 更新用户信息 | `{id, ...fields}` | `{user, error}` |
| `User.delete()` | 删除用户 | `{id}` | `boolean` |
| `User.canSendChat()` | 检查每日消息限额 | `user` | `boolean` |
| `User.filterFields()` | 过滤敏感字段 | `user` | `safeUser` |

### 4.2 密码安全

```javascript
// 创建用户时的密码复杂度检查
create: async function ({ username, password, role = "default", ... }) {
  const passwordCheck = this.checkPasswordComplexity(password);
  if (!passwordCheck.checkedOK) {
    return { user: null, error: passwordCheck.error };
  }
  // ... bcrypt 哈希后存储
}
```

**`checkPasswordComplexity()`**：检查密码长度、复杂度（具体实现需查看完整代码）。

### 4.3 字段验证

```javascript
validations: {
  username: (newValue = "") => {
    if (username.length > 64) throw new Error("Username cannot be longer than 64 characters");
    if (username.length < 2) throw new Error("Username must be at least 2 characters");
    if (!User.usernameRegex.test(username)) throw new Error("...");
    return username;
  },
  role: (role = "default") => {
    const VALID_ROLES = ["default", "admin", "manager"];
    if (!VALID_ROLES.includes(role)) throw new Error("Invalid role");
    return String(role);
  },
  // ...
}
```

**设计模式**：策略模式。每个字段有独立的验证函数，通过 `writable` 数组声明可写字段，`castColumnValue()` 处理类型转换。

## 5. 安全加固建议

| 问题 | 风险 | 建议 |
|------|------|------|
| `cors({ origin: true })` | CSRF | 配置具体域名白名单 |
| 开发模式绕过认证 | 误配置导致未授权访问 | 生产环境强制校验 `NODE_ENV` |
| 无登录速率限制 | 暴力破解 | 添加 `express-rate-limit` |
| 无账户锁定机制 | 持续暴力破解 | 连续失败后临时锁定 |
| Session 无安全标志 | Session 劫持 | 设置 `cookie.secure`、`cookie.httpOnly`、`cookie.sameSite` |
| bcrypt.hashSync 每次请求计算 | 性能开销 | 缓存哈希结果 |
