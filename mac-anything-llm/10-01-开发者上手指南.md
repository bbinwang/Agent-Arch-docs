## 1. 环境准备

### 1.1 系统要求

| 组件 | 最低要求 | 推荐 |
|------|---------|------|
| Node.js | ≥ 18.12.1 | LTS (20.x) |
| 内存 | 4 GB | 8 GB+ |
| 磁盘 | 10 GB 可用 | 50 GB+ SSD |
| 操作系统 | macOS / Linux / Windows (WSL2) | Ubuntu 22.04 / macOS 14+ |

### 1.2 依赖安装

```bash
# 安装 Node.js（推荐使用 nvm）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
nvm install 18
nvm use 18

# 安装 Yarn
npm install -g yarn

# 安装 FFmpeg（文档处理依赖）
# macOS
brew install ffmpeg
# Ubuntu
sudo apt install ffmpeg
```

## 2. 本地运行

### 2.1 克隆与安装

```bash
# 克隆仓库
git clone https://github.com/mintplex-labs/anything-llm.git
cd anything-llm

# 安装所有依赖（server + collector + frontend）
yarn setup
```

`yarn setup` 实际执行：
```bash
cd server && yarn
cd ../collector && yarn
cd ../frontend && yarn
cd .. && yarn setup:envs && yarn prisma:setup
```

### 2.2 环境变量配置

```bash
# 复制环境变量模板
cp server/.env.example server/.env.development
cp frontend/.env.example frontend/.env
cp collector/.env.example collector/.env

# 编辑 server/.env.development
# 至少配置以下项：
LLM_PROVIDER=openai
OPEN_AI_KEY=sk-your-key
EMBEDDING_ENGINE=native
VECTOR_DB=lancedb
```

### 2.3 数据库初始化

```bash
# 生成 Prisma 客户端
yarn prisma:generate

# 执行数据库迁移
yarn prisma:migrate

# 可选：加载种子数据
yarn prisma:seed
```

### 2.4 启动开发服务

```bash
# 方式 1：一键启动（三个服务）
yarn dev

# 方式 2：分别启动（推荐，便于调试）
# 终端 1：API Server
yarn dev:server

# 终端 2：Collector
yarn dev:collector

# 终端 3：前端
yarn dev:frontend
```

启动后访问：
- 前端：`http://localhost:5173`
- API：`http://localhost:3001`
- API 文档：`http://localhost:3001/api/docs`

创建 `.vscode/launch.json`：

```json

  "configurations": [

      "type": "node",
      "request": "launch",

      "skipFiles": ["<node_internals>/**"],

      "env": {
        "NODE_ENV": "development"
      },
      "console": "integratedTerminal"
    },
    {
      "type": "node",
      "request": "launch",
      "name": "Debug Collector",
      "skipFiles": ["<node_internals>/**"],
      "program": "${workspaceFolder}/collector/index.js",
      "env": {
        "NODE_ENV": "development"
      },
      "console": "integratedTerminal"
    }
  ]
}
```

### 3.2 常用调试技巧

```bash
# 查看 Prisma 生成的 SQL 查询
DEBUG=prisma:query yarn dev:server

# 查看 HTTP 请求日志
ENABLE_HTTP_LOGGER=true yarn dev:server

# 重置数据库
yarn prisma:reset
```

## 4. 测试流程

### 4.1 运行测试

```bash
# 运行所有测试
yarn test

# 运行 Server 测试
cd server && yarn test

# 运行 Collector 测试
cd collector && yarn test

# 带覆盖率
cd server && yarn test --coverage
```

### 4.2 测试结构

```
server/__tests__/
├── models/          ← 数据模型单元测试
│   ├── user.test.js
│   └── ...
└── utils/           ← 工具函数单元测试
    ├── ...
    └── ...

collector/__tests__/
└── utils/
    └── ...
```

### 4.3 编写测试示例

```javascript
// server/__tests__/models/user.test.js
const { User } = require("../../models/user");

describe("User Model", () => {
  test("should create a user with valid data", async () => {
    const result = await User.create({
      username: "testuser",
      password: "password123!",
    });
    expect(result.user).toBeDefined();
    expect(result.user.username).toBe("testuser");
  });

  test("should reject invalid username", async () => {
    const result = await User.create({
      username: "123invalid",  // 数字开头
      password: "password123!",
    });
    expect(result.error).toBeDefined();
  });
});
```

## 6. 贡献流程

### 6.1 提交 PR

1. Fork 仓库
2. 创建功能分支：`git checkout -b feat/my-feature`
3. 提交更改：`git commit -m "feat: add my feature"`
4. 推送分支：`git push origin feat/my-feature`
5. 在 GitHub 创建 Pull Request
6. 等待 CI 通过 + Code Review

### 6.2 PR 检查清单

- [ ] 代码通过 ESLint 检查
- [ ] 测试通过
- [ ] 新增功能有测试覆盖
- [ ] 文档已更新（如需要）
- [ ] 无敏感信息泄露

### 6.3 PR 模板

参考 `.github/pull_request_template.md`。

## 7. 常见问题

### 7.1 安装问题

| 问题 | 解决方案 |
|------|---------|
| `node-gyp` 编译失败 | 安装 `build-essential`（Linux）或 Xcode Command Line Tools（macOS） |
| Puppeteer 下载失败 | 设置 `PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true`，手动安装 Chromium |
| Prisma 迁移失败 | 检查数据库连接，运行 `yarn prisma:reset` |

### 7.2 运行问题

| 问题 | 解决方案 |
|------|---------|
| 端口被占用 | 修改 `SERVER_PORT` 环境变量 |
| LLM API 超时 | 检查 API Key 和网络连接 |
| 向量库报错 | 检查 `VECTOR_DB` 配置，确保对应服务运行 |

### 7.3 Docker 问题

| 问题 | 解决方案 |
|------|---------|
| 权限错误 | 检查 `UID`/`GID` 环境变量 |
| 存储卷挂载失败 | 确保宿主机目录存在且有权限 |
| Chromium 启动失败 | 检查 `SYS_ADMIN` capability 是否添加 |
