## 3.2 流程分级约定

为确保图表的可读性与准确性，本章流程采用 **三级细化** 策略：

| 级别 | 粒度 | 适用场景 |
|------|------|---------|
| **L1 概览级** | 系统级交互（用户 ↔ 前端 ↔ 后端 ↔ 外部服务） | 理解端到端流程 |
| **L2 模块级** | 模块间调用（Router → Model → Service → DB） | 理解模块协作 |
| **L3 函数级** | 具体函数调用与数据变换 | 理解实现细节 |

每个子文件至少包含一张 **L1 或 L2 时序图**，复杂流程（如 Agent、RAG）额外提供 **L3 流程图**。

## 3.3 通用异常处理模式

AnythingLLM 的核心流程遵循统一的异常处理模式，在后续子文件中不再重复说明：

1. **HTTP 层**：`try/catch` 包裹路由处理函数，异常时返回 JSON 错误或 SSE abort 事件。
2. **SSE 流式层**：通过 `writeResponseChunk(response, { type: "abort", error })` 向前端推送错误事件，前端据此终止流并显示错误。
3. **模型层**：Prisma 操作使用 `try/catch` 捕获 `PrismaClientKnownRequestError`（如 P2002 唯一约束冲突），转换为业务错误消息。
4. **Collector 层**：文档处理失败返回 `{ success: false, reason }` 而非抛出异常，避免影响其他文档。
5. **Agent 层**：aibitat 框架通过 `APIError` 封装错误，通过 EventEmitter 通知前端。
