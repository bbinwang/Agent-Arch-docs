## 9.1 当前架构的优点

### 9.1.1 配置驱动设计

**优点**：
- 用户无需编码即可配置整个 RAG 流水线
- YAML 格式可读性强，支持注释
- Pydantic 验证提供清晰的错误信息

**体现**：
```yaml
# 用户只需修改 YAML 即可切换模型
llm:
  type: openai  # 改为 huggingface 即可切换
  params:
    model_kwargs:
      model_name: gpt-4o-mini
```

### 9.1.2 插件式解析器架构

**优点**：
- 新增解析器无需修改现有代码
- 按扩展名自动路由
- 支持回退到通用解析器

**体现**：
```python
self._splitter_conf = {
    "md": markdown_splitter,
    "docx": docx_splitter,
    "pdf": PDFSplitter(chunk_overlap=200).split_document,
}
self._fallback_splitter = UnstructuredSplitter().split_document
```

### 9.1.3 混合检索策略

**优点**：
- 稀疏检索（SPLADE）+ 密集检索（ChromaDB）互补
- 重排序提升最终检索质量
- 支持多种重排序模型切换

### 9.1.4 增量更新机制

**优点**：
- 基于文件 Hash 的差异检测
- 只处理变更文件，节省计算资源
- 支持新增、修改、删除三种变更类型

### 9.1.5 多种交互方式

**优点**：
- CLI：适合脚本化和自动化
- Web UI：适合非技术用户
- API：适合集成到其他系统
- MCP：适合与 AI 工具链集成

## 9.2 当前架构的缺点

### 9.2.1 内存管理问题

**问题描述**：
- 模型加载后常驻内存，缺乏自动卸载机制
- 索引更新时需要手动调用 `unload_model()`
- 多模型切换时可能导致 GPU 内存泄漏

**代码体现**：
```python
# api.py 中需要手动卸载
def unload_model(llm_bundle: LLMBundle):
    llm_bundle.store = None
    llm_bundle.chain = None
    # ... 手动清理每个引用
```

**风险**：长时间运行可能导致 OOM

### 9.2.2 单线程限制

**问题描述**：
- FastAPI 端点是同步的（`def` 而非 `async def`）
- LLM 推理阻塞事件循环
- 无法并发处理多个请求

**代码体现**：
```python
@api_app.get("/llm", ...)
async def llmsearch(...):  # 声明为 async 但内部是同步调用
    output = get_and_parse_response(...)  # 同步阻塞
```

### 9.2.3 错误处理不完善

**问题描述**：
- 部分函数缺少异常处理
- 错误信息不够友好
- 缺乏重试机制（除图片解析外）

**代码体现**：
```python
# process.py 中直接抛出 TypeError
if llm_bundle.hyde_chain is None:
    raise TypeError("HyDE chain is not initialised. exiting.")
```

### 9.2.4 代码重复

**问题描述**：
- `unload_model()` 在 `api.py` 和 `webapp.py` 中重复实现
- `load_yaml_file()` 在 `config.py` 和 `webapp.py` 中重复实现
- `set_cache_folder()` 在 `utils.py` 和 `api.py` 中重复实现

### 9.2.5 测试覆盖不足

**问题描述**：
- 仅有 4 个测试文件
- 缺少核心模块的单元测试
- 缺少集成测试

**现有测试**：
```
tests/
├── test_config.py              # 配置加载测试
├── test_table_splitting.py     # 表格分片测试
├── test_conversation_history.py # 对话历史测试
└── test_embeddings_update.py   # 嵌入更新测试
```

## 9.3 可扩展性建议

### 9.3.1 支持更多向量数据库

**当前**：仅支持 ChromaDB

**建议**：
```python
# 在 VectorStore 抽象基类下添加更多实现
class VectorStoreFAISS(VectorStore):
    """FAISS 实现，适合大规模向量检索"""
    pass

class VectorStoreMilvus(VectorStore):
    """Milvus 实现，适合分布式部署"""
    pass
```

### 9.3.2 支持异步处理

**建议**：
```python
# 使用异步 LLM 调用
from langchain_core.runnables import Runnable

async def llmsearch_async(question):
    result = await llm_bundle.chain.ainvoke({"context": docs, "question": question})
    return result
```

### 9.3.3 支持流式输出

**建议**：
```python
# 使用 SSE 流式返回 LLM 生成结果
from fastapi.responses import StreamingResponse

@api_app.get("/llm/stream")
async def llmsearch_stream(question: str):
    async def generate():
        async for chunk in llm_bundle.chain.astream({"context": docs, "question": question}):
            yield f"data: {chunk}\n\n"
    return StreamingResponse(generate(), media_type="text/event-stream")
```

### 9.3.4 支持多租户

**建议**：
- 为每个用户分配独立的嵌入存储路径
- 添加用户认证和授权
- 支持用户级别的配置隔离

## 9.4 安全加固建议

### 9.4.1 API 认证

**当前**：API 端点无认证

**建议**：
```python
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials

security = HTTPBearer()

@api_app.get("/llm")
async def llmsearch(
    credentials: HTTPAuthorizationCredentials = Depends(security),
    ...
):
    if not verify_token(credentials.credentials):
        raise HTTPException(status_code=401, detail="Unauthorized")
```

### 9.4.2 输入校验

**建议**：
```python
from pydantic import Field

class QueryRequest(BaseModel):
    question: str = Field(..., min_length=1, max_length=10000)
    label: str = Field("", max_length=100)
```

### 9.4.3 密钥管理

**当前**：API Key 存储在 .env 文件

**建议**：
- 使用密钥管理服务（如 AWS Secrets Manager、Azure Key Vault）
- 支持运行时密钥轮换
- 添加密钥权限最小化

### 9.4.4 CORS 限制

**当前**：`allow_origins=["*"]`

**建议**：
```python
origins = [
    "https://your-domain.com",
    "http://localhost:3000",
]
```

## 9.5 性能优化建议

### 9.5.1 嵌入缓存

**建议**：
- 对重复查询的嵌入结果进行缓存
- 使用 Redis 作为分布式缓存

```python
import redis

cache = redis.Redis(host='localhost', port=6379)

def get_embedding_with_cache(text):
    cached = cache.get(f"emb:{hash(text)}")
    if cached:
        return json.loads(cached)
    embedding = model.embed(text)
    cache.set(f"emb:{hash(text)}", json.dumps(embedding), ex=3600)
    return embedding
```

### 9.5.2 批量推理

**建议**：
- 对多个查询进行批量嵌入
- 对多个 query-document 对进行批量重排序

### 9.5.3 索引分片

**建议**：
- 对大规模文档集进行分片
- 并行处理多个分片

### 9.5.4 GPU 利用率优化

**建议**：
- 使用 TensorRT 加速推理
- 使用 FP16 混合精度
- 使用 vLLM 加速 LLM 推理

## 9.6 重构建议

### 9.6.1 提取公共模块

**建议**：将重复代码提取到公共模块

```python
# llmsearch/common.py
def unload_model(llm_bundle: LLMBundle):
    """统一的模型卸载函数"""
    ...

def load_yaml_file(config) -> dict:
    """统一的 YAML 加载函数"""
    ...

def set_cache_folder(cache_folder_root: str):
    """统一的缓存设置函数"""
    ...
```

### 9.6.2 统一错误处理

**建议**：定义统一的异常体系

```python
# llmsearch/exceptions.py
class LLMSearchError(Exception):
    """基础异常"""
    pass

class ConfigError(LLMSearchError):
    """配置错误"""
    pass

class EmbeddingError(LLMSearchError):
    """嵌入错误"""
    pass

class RetrievalError(LLMSearchError):
    """检索错误"""
    pass
```

### 9.6.3 配置模型优化

**建议**：将配置模型拆分到独立文件

```
llmsearch/config/
    ├── __init__.py
    ├── base.py          # 基础配置
    ├── embeddings.py    # 嵌入配置
    ├── search.py        # 搜索配置
    ├── llm.py           # LLM 配置
    └── models.py        # Pydantic 模型
```

## 9.7 技术债清单

### 9.7.1 高优先级

| # | 技术债 | 影响 | 建议 |
|---|--------|------|------|
| 1 | 测试覆盖不足 | 代码质量风险 | 为核心模块添加单元测试 |

| 3 | 代码重复 | 维护成本 | 提取公共模块 |

## 9.8 未来规划建议

### 9.8.1 短期（1-3 个月）

1. **完善测试覆盖**：为核心模块添加单元测试和集成测试
2. **异步化改造**：将同步 API 改为异步
3. **安全加固**：添加 API 认证和输入校验
4. **代码重构**：提取公共模块，消除重复代码

### 9.8.2 中期（3-6 个月）

1. **流式输出**：支持 SSE 流式返回 LLM 生成结果
2. **多向量数据库**：支持 FAISS、Milvus 等
3. **监控告警**：添加 Prometheus 指标和 Grafana 仪表盘
4. **多租户支持**：支持用户隔离和权限管理

### 9.8.3 长期（6-12 个月）

1. **分布式部署**：支持 Kubernetes 部署和水平扩展
2. **自动调优**：基于反馈自动调整检索参数
3. **多语言支持**：支持中文等非英语文档的优化处理
4. **知识图谱**：结合知识图谱增强检索
