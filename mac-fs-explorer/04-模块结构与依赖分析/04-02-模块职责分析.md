# 04-02 — 模块职责分析

> **本章内容**: 每个主要目录/模块的功能职责、输入输出
> **预估字数**: ~8,000 字

---

## 1. 模块划分总览

fs-explorer 项目采用 Monorepo 结构，包含 4 个独立包：

```
fs-explorer (主包)
    ├── 文件系统探索 Agent
    ├── CLI 接口
    └── 磁盘缓存

rag-starterkit (RAG 对比包)
    ├── 文档解析
    ├── 文本分块
    ├── 嵌入生成
    ├── 向量存储
    └── 混合检索

eval-framework (评估包)
    ├── 双框架运行
    ├── LLM 评估
    └── 统计报告

cache-arxiv (工具包)
    └── arXiv 论文缓存
```

## 2. fs_explorer 主包

### 2.1 main.py — CLI 入口模块

| 属性 | 说明 |
|------|------|
| **职责** | 命令行接口定义、事件渲染、用户交互 |
| **输入** | CLI 参数（task/directory/recursive/skip/file/max_chars） |
| **输出** | 终端渲染（Rich Panel/Status） |
| **依赖** | typer, rich, asyncio, workflow, caching |
| **核心函数** | `run_workflow(task)`, `load_cache(directory, recursive, to_skip)`, `get_cached(file, max_chars)` |

**详细职责**:
1. 定义 3 个 CLI 命令：`run`、`load-cache`、`get-cached`
2. 启动异步事件循环（`asyncio.run()`）
3. 订阅工作流事件流（`stream_events()`）
4. 根据事件类型渲染不同的 Rich 面板
5. 处理人机交互（AskHumanEvent → 用户输入 → HumanAnswerEvent）

### 2.2 agent.py — Agent 核心模块

| 属性 | 说明 |
|------|------|
| **职责** | 封装 Gemini 客户端，管理对话历史，执行工具调用 |
| **输入** | 系统提示、用户任务、工具结果、用户回答 |
| **输出** | Action 决策（toolcall/godeeper/askhuman/stop） |
| **依赖** | google.genai, fs, models |
| **核心类** | `FsExplorerAgent` |

**详细职责**:
1. 初始化 Gemini 客户端（`GenAIClient`）
2. 管理对话历史（`_chat_history: list[Content]`）
3. 配置任务（`configure_task()`）
4. 获取决策（`take_action()`）— 调用 Gemini 并解析 Action
5. 执行工具（`call_tool()`）— 查找注册表并调用工具函数

### 2.3 workflow.py — 工作流编排模块

| 属性 | 说明 |
|------|------|
| **职责** | 定义 4 步状态机，管理事件流转和状态 |
| **输入** | InputEvent（用户任务） |
| **输出** | ExplorationEndEvent（最终结果） |
| **依赖** | llama-index-workflows, agent, models, fs |
| **核心类** | `FsExplorerWorkflow`, `WorkflowState`, 事件类 |

**详细职责**:
1. 定义工作流状态（`WorkflowState`: initial_task, current_directory）
2. 定义事件类型（InputEvent, GoDeeperEvent, ToolCallEvent, AskHumanEvent, HumanAnswerEvent, ExplorationEndEvent）
3. 实现 4 个步骤（start_exploration, go_deeper_action, tool_call_action, receive_human_answer）
4. 注入 Agent 资源（`Resource(get_agent)`）
5. 设置工作流超时（120s）

### 2.4 fs.py — 文件系统工具模块

| 属性 | 说明 |
|------|------|
| **职责** | 提供 5 个文件系统工具函数 |
| **输入** | 文件路径、搜索模式 |
| **输出** | 操作结果字符串 |
| **依赖** | os, re, glob, llama_cloud_services, caching |
| **核心函数** | `describe_dir_content()`, `read_file()`, `grep_file_content()`, `glob_paths()`, `check_api_key()`, `parse_file()` |

**详细职责**:
1. `describe_dir_content(directory)`: 描述目录内容（FILES + SUBFOLDERS）
2. `read_file(file_path)`: 读取文本文件内容
3. `grep_file_content(file_path, pattern)`: 正则搜索文件内容
4. `glob_paths(directory, pattern)`: 文件名模式匹配
5. `check_api_key()`: 检查 LlamaParse API Key 状态
6. `parse_file(file_path)`: 解析非结构化文档（优先从缓存读取）

### 2.5 models.py — 数据模型模块

| 属性 | 说明 |
|------|------|
| **职责** | 定义 Pydantic 模型和类型别名 |
| **输入** | JSON 数据（来自 Gemini 响应） |
| **输出** | 类型安全的 Python 对象 |
| **依赖** | pydantic, typing |
| **核心类** | `Action`, `ToolCallAction`, `GoDeeperAction`, `StopAction`, `AskHumanAction`, `ToolCallArg`, `WorkflowState` |

**详细职责**:
1. 定义类型别名（Tools, ActionType）
2. 定义 Action 联合类型（多态模型）
3. 提供类型转换方法（`to_action_type()`, `to_fn_args()`）
4. 定义工作流状态模型

### 2.6 caching.py — 缓存模块

| 属性 | 说明 |
|------|------|
| **职责** | 封装 DiskCache，提供文件解析结果缓存 |
| **输入** | 文件路径、解析内容 |
| **输出** | 缓存的解析内容 |
| **依赖** | diskcache, llama_cloud_services |
| **核心类** | `ParsedFileCache` |
| **核心函数** | `parse_and_cache()` |

**详细职责**:
1. 封装 DiskCache（SQLite 后端）
2. 提供 `add_file()` 和 `get_file()` 接口
3. 提供 `warmup()` 初始化缓存目录
4. 实现 `parse_and_cache()` 批量解析并缓存文件

## 3. rag-starterkit 包

### 3.1 pipeline.py — RAG 流水线模块

| 属性 | 说明 |
|------|------|
| **职责** | 编排 RAG 索引和检索两个阶段 |
| **输入** | 文档目录、查询字符串 |
| **输出** | 生成的回答、文件路径 |
| **依赖** | parse, chunk, embed, vectordb, llm_filter |
| **核心类** | `Pipeline` |

**详细职责**:
1. 管理解析策略选择（实时解析 vs 缓存加载）
2. 编排索引流程（parse → chunk → embed → upload）
3. 编排检索流程（filter → search → rerank → generate）
4. 管理组件生命周期（Chunker, Embedder, VectorDB, LLMFilter）

### 3.2 parse.py — 文档解析模块

| 属性 | 说明 |
|------|------|
| **职责** | 提供两种文档解析策略 |
| **输入** | 目录路径、递归标志、跳过列表 |
| **输出** | `{file_path: text}` 字典 |
| **依赖** | llama_cloud_services, diskcache |
| **核心函数** | `parse_directory()`, `contents_from_cache()` |

### 3.3 chunk.py — 文本分块模块

| 属性 | 说明 |
|------|------|
| **职责** | 将长文本切分为固定大小的块 |
| **输入** | `{file_path: text}` 字典 |
| **输出** | `list[ChunkWithMetadata]` |
| **依赖** | chonkie |
| **核心类** | `Chunker` |

### 3.4 embed.py — 嵌入生成模块

| 属性 | 说明 |
|------|------|
| **职责** | 为文本块生成稠密和稀疏嵌入 |
| **输入** | 文本块列表 |
| **输出** | 带嵌入的文本块列表 |
| **依赖** | openai, fastembed |
| **核心类** | `Embedder` |

### 3.5 vectordb.py — 向量数据库模块

| 属性 | 说明 |
|------|------|
| **职责** | 封装 Qdrant 操作，支持混合检索和 RRF 重排序 |
| **输入** | 文本块（带嵌入）、查询字符串 |
| **输出** | 检索结果列表 |
| **依赖** | qdrant_client |
| **核心类** | `VectorDB`, `SimpleReranker` |

### 3.6 llm_filter.py — LLM 过滤模块

| 属性 | 说明 |
|------|------|
| **职责** | 使用 LLM 筛选文件和生成回答 |
| **输入** | 查询字符串、文件列表、上下文 |
| **输出** | 筛选结果、生成的回答 |
| **依赖** | openai |
| **核心类** | `LLMFilter` |
