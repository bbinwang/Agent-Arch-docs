# 第九部分：改进建议、风险点与未来规划

## 9.1 当前架构优点

### 模块化清晰
- ai / agent-core / coding-agent 三层分离，职责明确
- 每层可独立复用和测试

### 扩展性强
- Extension API 提供 30+ 事件钩子
- 自定义工具、命令、UI 组件
- 社区可发布扩展包

### Provider 无关
- 43 个 provider 统一接口
- 用户可灵活切换，避免锁定

### 事件驱动
- Agent loop 通过事件流通信
- UI 通过订阅更新，解耦良好

### JSONL 可审计
- 完整会话记录，可回放、可调试
- 人类可读格式

### 差分渲染 TUI
- 高效、流畅的终端 UI
- 自研引擎，不依赖第三方

### 供应链安全到位
- 依赖锁定 + 审计 + 白名单
- 容器化指南

---

## 9.2 当前架构缺点与风险

### 单文件过大
- `agent-session.ts` 超过 1000 行，包含大量职责
- 违反单一职责原则，难以维护和测试

### any 残留
- 部分代码仍使用 `any` 类型（`tool_execution_start` 等事件）
- 降低类型安全性

### 测试覆盖不均
- 核心模块（agent-session、session-manager）测试覆盖不足
- 部分工具测试缺失

### Windows 兼容性补丁
- `cleanupWindowsSelfUpdateQuarantine` 等函数是特定问题的补丁
- 缺乏系统性的 Windows 兼容性处理

### 实验性 orchestrator
- `pi-orchestrator` 标记为实验性，API 不稳定
- 文档和测试不足

### 大文件处理
- JSONL 会话文件随时间增长，读取全部 entries 可能慢
- 需要更高效的索引或分页机制

---

## 9.3 可扩展性建议

### 扩展市场/注册表
- 建立扩展注册表，方便用户发现和安装扩展
- 扩展评分、审查机制

### 多会话并发
- 支持在同一 TUI 中切换多个活跃会话
- 会话标签页

### 远程会话
- 支持将会话同步到云端
- 跨设备继续工作

### 语言服务器集成
- 集成 LSP，获取代码补全、诊断信息
- Agent 可利用 LSP 信息做出更明智的决策

---

## 9.4 安全加固建议

### 工具沙箱强化
- 内置 Docker/Podman 沙箱选项
- 细粒度的文件系统访问控制

### Prompt Injection 防护
- 检测和防止 prompt injection 攻击
- 工具输入验证

### 凭证加密
- auth.json 中的凭证使用更强的加密
- 支持硬件安全模块（TPM、Secure Enclave）

### 审计日志
- 完整的操作审计日志
- 支持导出和查询

---

## 9.5 性能优化建议

### 启动延迟
- 延迟加载非核心模块
- 预编译常用扩展

### JSONL 大文件处理
- 实现会话文件索引
- 分页加载 entries

### Token 估算精度
- 使用更精确的 token 计数方法
- 针对不同模型使用不同的估算策略

### 流式工具调用
- 支持工具结果的流式返回
- 减少长时间运行工具的等待时间

---
