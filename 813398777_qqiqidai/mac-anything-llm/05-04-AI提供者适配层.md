## 1. 架构概述

AI 提供者适配层是 AnythingLLM **最庞大的插件体系**，支持 40+ LLM Provider。每个 Provider 是一个独立目录，实现统一的接口契约。

### 1.1 接口契约

每个 Provider 类需实现以下核心方法：

| 方法 | 功能 | 返回值 |
|------|------|--------|
| `constructor(embedder, modelPreference)` | 初始化 SDK 客户端 | — |
| `getChatCompletion(messages, options)` | 获取聊天完成 | `string` 或 `stream` |
| `streamGetChatCompletion(messages, options)` | 流式聊天完成 | `AsyncIterable` |
| `getEmbedding(text)` | 获取文本嵌入 | `number[]` |
| `promptWindowLimit()` | 返回模型上下文窗口大小 | `number` |
| `streamingEnabled()` | 是否支持流式 | `boolean` |
| `isValidChatCompletionModel(modelName)` | 验证模型是否可用 | `Promise<boolean>` |

### 1.2 目录结构

```
server/utils/AiProviders/
├── openAi/           ← OpenAI 官方

```

## 2. OpenAI Provider 实现

### 2.1 类结构

```javascript
class OpenAiLLM {
  constructor(embedder = null, modelPreference = null) {
    if (!process.env.OPEN_AI_KEY) throw new Error("No OpenAI API key was set.");
    this.className = "OpenAiLLM";
    const { OpenAI: OpenAIApi } = require("openai");

    this.openai = new OpenAIApi({
      apiKey: process.env.OPEN_AI_KEY,
    });
    this.model = modelPreference || process.env.OPEN_MODEL_PREF || "gpt-4.1-nano";
    this.limits = {
      history: this.promptWindowLimit() * 0.15,
      system: this.promptWindowLimit() * 0.15,
      user: this.promptWindowLimit() * 0.7,
    };
    this.embedder = embedder ?? new NativeEmbedder();
    this.defaultTemp = 0.7;
  }
}
```

**关键设计**：
- **Token 预算分配**：将上下文窗口按比例分配给 history（15%）、system（15%）、user（70%）。
- **默认嵌入器**：若未指定 embedder，使用 `NativeEmbedder`（本地嵌入模型）。

### 2.2 流式响应实现

```javascript
async streamGetChatCompletion(messages, { temperature, ... }) {
  const stream = await this.openai.chat.completions.create({
    model: this.model,
    messages,
    temperature: temperature || this.defaultTemp,
    stream: true,
  });

  for await (const chunk of stream) {
    const content = chunk.choices[0]?.delta?.content;
    if (content) yield { output: content };
  }
}
```

**设计模式**：使用 `AsyncIterable` 实现流式输出，调用方通过 `for await...of` 消费。

### 2.3 上下文窗口管理

```javascript
static promptWindowLimit(modelName) {
  return MODEL_MAP.get("openai", modelName) ?? 4_096;
}

promptWindowLimit() {
  return MODEL_MAP.get("openai", this.model) ?? 4_096;
}
```

**MODEL_MAP**：从 `modelMap/index.js` 获取模型的上下文窗口大小，支持动态更新。

## 3. MODEL_MAP — 模型注册表

### 3.1 功能

`server/utils/AiProviders/modelMap/index.js` 维护一个全局的 **模型 → 上下文窗口大小** 映射表，支持：
- 本地缓存（JSON 文件）
- 远程拉取（LiteLLM 的 model_prices_and_context_window.json）
- 缓存过期（3 天）

### 3.2 ContextWindowFinder

```javascript
class ContextWindowFinder {
  static remoteUrl = "https://raw.githubusercontent.com/BerriAI/litellm/.../model_prices_and_context_window.json";
  static expiryMs = 1000 * 60 * 60 * 24 * 3; // 3 天

  get isCacheStale() {
    if (!fs.existsSync(this.cacheFileExpiryPath)) return true;
    const cachedAt = fs.readFileSync(this.cacheFileExpiryPath, "utf8");
    return Date.now() - cachedAt > ContextWindowFinder.expiryMs;
  }

  async #pullRemoteModelMap() {
    const response = await fetch(ContextWindowFinder.remoteUrl);
    const data = await response.json();
    fs.writeFileSync(this.cacheFilePath, JSON.stringify(data, null, 2));
    fs.writeFileSync(this.cacheFileExpiryPath, String(Date.now()));
  }
}
```

**设计模式**：单例模式（`ContextWindowFinder.instance`）+ 懒加载缓存。

### 3.3 模型映射格式

```javascript
// LiteLLM 模型映射（部分）

  // ...
```

## 4. Ollama Provider（本地模型）

### 4.1 特点

- **本地推理**：通过 Ollama 服务运行开源模型。
- **零 API 成本**：无需云 API 密钥。
- **支持嵌入**：可同时用于聊天和嵌入。

### 4.2 核心实现

```javascript
const Ollama = require("ollama").default;

class OllamaLLM {
  constructor(embedder = null, modelPreference = null) {
    this.className = "OllamaLLM";
    this.ollama = new Ollama({ host: process.env.OLLAMA_BASE_PATH });
    this.model = modelPreference || process.env.OLL_MODEL_PREF || "llama3";
    this.embedder = embedder ?? new OllamaEmbedder(this.ollama);
  }

  async streamGetChatCompletion(messages, options) {
    const stream = await this.ollama.chat({
      model: this.model,
      messages,
      stream: true,
      options: { temperature: options.temperature || 0.7 },
    });
    for await (const chunk of stream) {
      if (chunk.message?.content) yield { output: chunk.message.content };
    }
  }
}
```

## 5. Anthropic Provider

### 5.1 特点

- **System Prompt 分离**：Anthropic API 将 system 作为独立参数，而非 messages 数组中的 role: "system"。
- **多模态支持**：支持图片输入（base64 编码）。

### 5.2 消息格式转换

```javascript
class AnthropicLLM {
  async streamGetChatCompletion(messages, options) {
    // 将 OpenAI 格式转换为 Anthropic 格式
    const systemMessage = messages.find(m => m.role === "system");
    const chatMessages = messages.filter(m => m.role !== "system");

    const stream = await this.anthropic.messages.create({
      model: this.model,
      system: systemMessage?.content,
      messages: chatMessages,
      max_tokens: 4096,
      stream: true,
    });

    for await (const event of stream) {
      if (event.type === "content_block_delta") {
        yield { output: event.delta.text };
      }
    }
  }
}
```

## 6. 通用 OpenAI 兼容 Provider

### 6.1 设计

`genericOpenAi/` 实现了 OpenAI API 兼容接口，可用于：
- vLLM
- TextGen WebUI
- KoboldCPP
- LocalAI
- 其他 OpenAI-compatible 服务

```javascript
class GenericOpenAiLLM {

    this.openai = new OpenAI({
```

## 7. 潜在问题与改进建议

| 问题 | 影响 | 建议 |
|------|------|------|
| 40+ Provider 目录结构相似 | 代码重复 | 提取公共基类 `BaseLLMProvider` |
| 上下文窗口硬编码默认值 | 新模型可能不准确 | 添加模型自动发现机制 |
| 无 Provider 健康检查 | 故障时才发现 | 添加定期健康检查 |
| 流式错误处理不一致 | 部分 Provider 错误丢失 | 统一流式错误封装 |
| Token 估算不准确 | 上下文溢出 | 使用 js-tiktoken 精确计算 |
