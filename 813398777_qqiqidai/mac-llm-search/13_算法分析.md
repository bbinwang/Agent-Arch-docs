## 13.1 SPLADE 稀疏嵌入算法

### 13.1.1 算法描述

SPLADE（Sparse Lexical and Expansion Model）通过学习稀疏向量表示，将文本映射到词汇表维度的稀疏空间。

### 13.1.2 伪代码

```
算法：SPLADE 嵌入生成
输入：文档列表 D = [d1, d2, ..., dn]
输出：稀疏嵌入矩阵 V ∈ R^(n×|vocab|)

1. 加载预训练模型 M（naver/splade-cocondenser-ensembledistil）
2. 加载分词器 T
3. for each batch B ⊆ D:
   a. tokens = T(B, padding=True, truncation=True)
   b. output = M(**tokens)
   c. logits = output.logits  # shape: (batch_size, seq_len, vocab_size)
   d. mask = tokens.attention_mask  # shape: (batch_size, seq_len)
   e. vecs = max_over_time(log(1 + ReLU(logits)) * mask)
      # shape: (batch_size, vocab_size)
   f. 将 vecs 添加到列表
4. V = vstack(all_vecs)  # shape: (n, vocab_size)
5. 返回 V
```

### 13.1.3 数学公式

$$\mathbf{v}_d = \max_{t \in [1, T]} \left( \log(1 + \text{ReLU}(\mathbf{l}_t)) \cdot \mathbf{m}_t \right)$$

其中：
- $\mathbf{l}_t$ 是第 $t$ 个 token 的 logits 向量
- $\mathbf{m}_t$ 是 attention mask（0 或 1）
- $\max$ 是逐元素取最大值

### 13.1.4 时间复杂度

| 步骤 | 复杂度 | 说明 |
|------|--------|------|
| 分词 | $O(n \cdot L)$ | $n$ 为文档数，$L$ 为序列长度 |
| 模型推理 | $O(n \cdot L \cdot d_{model})$ | $d_{model}$ 为模型维度 |
| ReLU + Log | $O(n \cdot L \cdot |V|)$ | $|V|$ 为词汇表大小 |
| Max pooling | $O(n \cdot L \cdot |V|)$ | 逐元素取最大值 |
| **总计** | $O(n \cdot L \cdot d_{model})$ | 主导项是模型推理 |

### 13.1.5 空间复杂度

- 稀疏矩阵：$O(n \cdot k)$，$k$ 为每文档非零元素数（通常 $k \ll |V|$）
- 使用 CSR 格式压缩存储

### 13.1.6 检索算法

```
算法：SPLADE 检索
输入：查询 q，chunk_size c，标签 l，返回数量 k
输出：文档 ID 列表和分数

1. 根据 l 和 c 获取索引集合 I
2. embeddings = self._embeddings[I]  # 子矩阵
3. ids = self._ids[I]
4. l2_norms = self._l2_norm_matrix[I]  # 预计算
5. query_vec = embed_query(q)  # 单次嵌入
6. l2_norm_query = norm(query_vec)
7. cosine_sim = embeddings.dot(query_vec) / (l2_norms * l2_norm_query)
8. top_indices = argsort(cosine_sim)[-k:].reverse()
9. return ids[top_indices], cosine_sim[top_indices]
```

### 13.1.7 优化建议

1. **批量查询**：对多个查询并行嵌入
2. **ANN 索引**：使用 FAISS 的 IVF 或 HNSW 索引加速
3. **量化**：对稀疏向量进行量化压缩

## 13.2 Markdown 递归逻辑分片算法

### 13.2.1 算法描述

`get_logical_blocks_recursively` 按标题层级递归分割 Markdown 文档，保留文档的逻辑结构。

### 13.2.2 伪代码

```
算法：递归逻辑分片
输入：markdown 文本 M，最大分片大小 S，分片级别 L
输出：分片列表 C

1. if L >= len(BLOCK_SPLIT_CANDIDATES):
   # 基础情况：物理分片
   for chunk in physical_split(M, S):
       C.append(MarkdownChunk(string=chunk, level=L))
   return C

2. # 尝试当前级别的分割
3. for i, candidate in enumerate(BLOCK_SPLIT_CANDIDATES[L:]):
   4. chunks = re.split(candidate, M)
   5. if len(chunks) > 1:
       # 找到有效的分割
       6. for j, chunk in enumerate(chunks):
           7. level = L + i + (1 if j > 0 else 0)
           8. prefix = "\n\n" + "#" * level + " "
           9. if len(chunk) <= S:
               10. C.append(MarkdownChunk(string=prefix + chunk, level=level-1))
           11. else:
               12. get_logical_blocks_recursively(chunk, S, L+i+1)  # 递归
       13. return C

20. return C
```

### 13.2.3 时间复杂度

| 步骤 | 复杂度 | 说明 |
|------|--------|------|
| 正则分割 | $O(|M|)$ | 单次正则匹配 |
| 递归深度 | $O(H)$ | $H$ 为标题层级数（通常 ≤ 6） |
| 物理分片 | $O(|M|)$ | 线性扫描 |
| **总计** | $O(|M| \cdot H)$ | 最坏情况下每层都分割 |

### 13.2.4 空间复杂度

- $O(|M|)$：存储所有分片

### 13.2.5 优化建议

1. **缓存正则编译**：预编译 `BLOCK_SPLIT_CANDIDATES`
2. **尾递归优化**：转换为迭代实现
3. **并行分片**：对独立章节并行处理

## 13.3 增量更新 Hash Diff 算法

### 13.3.1 算法描述

`get_changed_or_new_files` 通过 Pandas outer join 对比新旧文件 Hash，识别新增、修改、删除的文件。

### 13.3.2 伪代码

```
算法：Hash 差异检测
输入：新 Hash 表 N，旧 Hash 表 E
输出：新增/修改文件 C，修改文件 H，删除文件 D

1. merged = N.merge(E, on=[filehash, filename], how='outer', indicator=True)
   # indicator=True 添加 _merge 列：left_only/right_only/both

2. # 新增或修改的文件（在新表中但不在旧表中）
3. C = merged[merged['_merge'] == 'left_only']

4. # 修改的文件（文件名相同但 Hash 不同）
5. duplicated = merged[filename].duplicated()
6. H = merged[duplicated]

7. # 删除的文件（在旧表中但不在新表中，且不是修改的）
8. deleted_mask = (merged['_merge'] == 'right_only') & \
                  (~merged['filename'].isin(H['filename']))
9. D = merged[deleted_mask]

10. return C, H, D
```

### 13.3.3 时间复杂度

| 步骤 | 复杂度 | 说明 |
|------|--------|------|
| Merge | $O(n + m)$ | $n$ 为新文件数，$m$ 为旧文件数 |
| 过滤 | $O(n + m)$ | 线性扫描 |
| **总计** | $O(n + m)$ | 线性复杂度 |

### 13.3.4 空间复杂度

- $O(n + m)$：存储合并后的表

### 13.3.5 优化建议

1. **增量 Hash**：只计算变更文件的 Hash
2. **索引加速**：为 filename 和 filehash 建立索引
3. **流式处理**：对大文件集分批处理

## 13.4 混合检索融合算法

### 13.4.1 算法描述

`get_relevant_documents` 实现稀疏+密集并行检索，结果取并集后重排序。

### 13.4.2 伪代码

```
算法：混合检索
输入：原始查询 Q，查询列表 Qs，LLM 依赖 B，配置 C
输出：排序文档列表 D，质量分数 S

1. best_score = -∞
2. for chunk_size in B.chunk_sizes:
   3. all_relevant_docs = []
   4. all_relevant_ids = {}
   5. for query in Qs:
       6. # 稀疏检索
       7. sparse_ids, sparse_scores = B.sparse_search.query(
           search=query, n=C.max_k, label=label, chunk_size=chunk_size)
       8. 
       9. # 密集检索
      10. filter = build_filter(chunk_size, label)
      11. dense_results = B.store.similarity_search_with_relevance_scores(
          query, k=C.max_k, filter=filter)
      12. dense_ids = [r.metadata['document_id'] for r in dense_results]
      13. 
      14. # 结果融合
      15. all_ids = set(sparse_ids) ∪ set(dense_ids) - all_relevant_ids
      16. docs = B.store.get_documents_by_id(list(all_ids))
      17. all_relevant_docs.extend(docs)
      18. all_relevant_ids = all_relevant_ids ∪ all_ids
   19. 
   20. # 重排序
   21. score, sorted_docs = rerank(B.reranker, Q, all_relevant_docs)
   22. if score > best_score:
   23.    D = sorted_docs
   24.    best_score = score
   25. 
26. # 上下文窗口裁剪
27. final_docs = []
28. total_len = 0
29. for doc in D:
   30.    if C.score_cutoff and doc.metadata['score'] < C.score_cutoff:
   31.        continue
   32.    if total_len + len(doc.page_content) < C.max_char_size:
   33.        final_docs.append(doc)
   34.        total_len += len(doc.page_content)
35. 
36. return final_docs, best_score
```

### 13.4.3 时间复杂度

| 步骤 | 复杂度 | 说明 |
|------|--------|------|
| 稀疏检索 | $O(|Qs| \cdot k \cdot |V|)$ | $k$ 为返回数，$|V|$ 为词汇表 |
| 密集检索 | $O(|Qs| \cdot k \cdot d)$ | $d$ 为嵌入维度 |
| 结果融合 | $O(|Qs| \cdot k)$ | 集合操作 |
| 重排序 | $O(|Docs| \cdot L \cdot d_{ce})$ | $L$ 为文档长度，$d_{ce}$ 为 cross-encoder 维度 |
| **总计** | $O(|Qs| \cdot k \cdot (d + |V|) + |Docs| \cdot L \cdot d_{ce})$ | |

### 13.4.4 优化建议

1. **并行检索**：稀疏和密集检索可并行执行
2. **批量重排序**：对多个文档对并行计算分数
3. **缓存嵌入**：缓存查询嵌入避免重复计算

## 13.5 HyDE 与 MultiQuery 算法

### 13.5.1 HyDE 算法

```
算法：HyDE（Hypothetical Document Embeddings）
输入：用户查询 Q，LLM 模型 M
输出：假设文档 H

1. prompt = "Write a short passage to answer the question: {Q}"
2. H = M.generate(prompt)
3. return H
```

**原理**：用 LLM 生成一个假设答案，用假设答案去检索，而不是用原始查询。

**优势**：当用户无法用领域特定语言提问时，假设答案能更好地匹配文档。

### 13.5.2 MultiQuery 算法

```
算法：MultiQuery（RAG Fusion 风格）
输入：用户查询 Q，LLM 模型 M，变体数量 N
输出：查询变体列表 Qs

1. prompt = """
   Generate {N} additional related questions related to: {Q}.
   Suggest only short questions without compound sentences.
   Suggest a variety of questions that cover different aspects.
   """
2. response = M.generate(prompt)
3. Qs = [q.strip() for q in response.split("\n") if q.strip()]
4. if len(Qs) != N:
   raise ValueError("生成的查询变体数量不匹配")
5. return Qs
```

**原理**：生成多个查询变体，覆盖不同角度和术语，提升检索召回率。

### 13.5.3 时间复杂度

| 算法 | 复杂度 | 说明 |
|------|--------|------|
| HyDE | $O(T_{LLM})$ | 单次 LLM 调用 |
| MultiQuery | $O(T_{LLM})$ | 单次 LLM 调用 |

### 13.5.4 优化建议

1. **缓存**：对重复查询缓存增强结果
2. **并行**：MultiQuery 的多个变体可并行检索
3. **异步**：使用 `ainvoke` 异步调用 LLM

## 13.6 算法复杂度总结

| 算法 | 时间复杂度 | 空间复杂度 | 瓶颈 |
|------|------------|------------|------|
| SPLADE 嵌入 | $O(n \cdot L \cdot d_{model})$ | $O(n \cdot k)$ | 模型推理 |
| Markdown 分片 | $O(\|M\| \cdot H)$ | $O(\|M\|)$ | 递归深度 |
| Hash Diff | $O(n + m)$ | $O(n + m)$ | Merge 操作 |
| 混合检索 | $O(\|Qs\| \cdot k \cdot (d + \|V\|))$ | $O(k \cdot d)$ | 重排序 |
| HyDE/MultiQuery | $O(T_{LLM})$ | $O(1)$ | LLM 延迟 |

## 13.7 本章小结

本章详细分析了 pyLLMSearch 的 5 个核心算法：

1. **SPLADE**：稀疏嵌入生成与检索，$O(n \cdot L \cdot d_{model})$
2. **Markdown 分片**：递归逻辑分片，$O(|M| \cdot H)$
3. **Hash Diff**：增量更新差异检测，$O(n + m)$
4. **混合检索**：稀疏+密集融合，$O(|Qs| \cdot k \cdot (d + |V|))$
5. **HyDE/MultiQuery**：查询增强，$O(T_{LLM})$
