## 1. Agent 初始化与首次决策

```mermaid
sequenceDiagram
    participant User
    participant CLI
    participant Workflow
    participant Agent
    participant Gemini

    User->>CLI: explore run --task "找到 PDF"
    CLI->>CLI: 解析参数
    CLI->>Workflow: workflow.run(InputEvent)
    Workflow->>Workflow: start_exploration 步骤
    Workflow->>Workflow: describe_dir_content(".")
    Workflow->>Agent: configure_task(任务描述)
    Agent->>Agent: 追加到 _chat_history
    Workflow->>Agent: take_action()
    Agent->>Gemini: generate_content(对话历史)
    Gemini-->>Agent: Action JSON (toolcall: read)
    Agent->>Agent: call_tool("read", {...})
    Agent-->>Workflow: (Action, "toolcall")
    Workflow->>Workflow: 发出 ToolCallEvent
    Workflow-->>CLI: ToolCallEvent
    CLI->>CLI: Rich 渲染面板
    CLI-->>User: 显示工具调用信息
```

**说明**: 该时序图展示了从用户执行命令到 Agent 完成首次工具调用的完整流程。CLI 解析参数后启动工作流，工作流调用 Agent 获取决策，Agent 调用 Gemini API 并执行工具调用，最后事件被渲染到终端。

## 2. 工具调用 → 结果回传 → 下一步决策

```mermaid
sequenceDiagram
    participant CLI
    participant Workflow
    participant Agent
    participant FS as FileSystem
    participant Gemini

    Workflow->>Agent: take_action()
    Agent->>Gemini: generate_content(历史)
    Gemini-->>Agent: Action: toolcall read
    Agent->>FS: read_file("test.txt")
    FS-->>Agent: 文件内容
    Agent->>Agent: 追加到 _chat_history
    Agent-->>Workflow: (Action, "toolcall")
    Workflow->>Workflow: 发出 ToolCallEvent
    Workflow-->>CLI: 事件
    CLI->>CLI: 渲染面板
    Workflow->>Workflow: tool_call_action 步骤
    Workflow->>Agent: configure_task("工具结果")
    Workflow->>Agent: take_action()
    Agent->>Gemini: generate_content(更新后的历史)
    Gemini-->>Agent: Action: stop
    Agent-->>Workflow: (Action, "stop")
    Workflow->>Workflow: ExplorationEndEvent
    Workflow-->>CLI: 最终结果
    CLI->>CLI: 渲染结果面板
```

**说明**: 展示了工具调用循环的完整生命周期。工具结果被追加到对话历史后，Agent 基于新的上下文继续决策，直到返回 stop 动作。

## 5. 缓存命中 vs 未命中

```mermaid
sequenceDiagram
    participant Agent
    participant FS as FileSystem
    participant Cache as DiskCache
    participant LlamaParse

    Note over Agent: 场景 1: 缓存命中
    Agent->>Cache: get_file("doc.pdf")
    Cache-->>Agent: 缓存的文本内容
    Note over Agent: 直接返回，无网络调用

    Note over Agent: 场景 2: 缓存未命中
    Agent->>Cache: get_file("doc.pdf")
    Cache-->>Agent: None
    Agent->>FS: 检查文件存在
    FS-->>Agent: 存在
    Agent->>LlamaParse: aparse("doc.pdf")
    LlamaParse-->>Agent: JobResult
    Agent->>LlamaParse: aget_text()
    LlamaParse-->>Agent: 解析后的文本
    Agent-->>Agent: 返回文本
```

**说明**: parse_file 工具的两条执行路径。缓存命中时直接返回（< 10ms），缓存未命中时调用 LlamaParse API（10-30s）。


**说明**: RAG 索引阶段的完整数据流。文档经过解析、分块、双嵌入生成后上传到 Qdrant。

**说明**: RAG 查询阶段的完整流程。先使用 LLM 筛选文件，然后进行混合检索和 RRF 重排序，最后基于上下文生成回答。

## 8. 评估框架双轨执行

```mermaid
sequenceDiagram
    participant Eval
    participant WF as AgentWorkflow
    participant Pipeline
    participant Judge as GPT-5.2

    Eval->>Eval: 加载数据集
    loop 每个任务
        Eval->>WF: run_workflow(question)
        WF-->>Eval: {time, answer, files, error}
        Eval->>Pipeline: run_pipeline(question)
        Pipeline-->>Eval: {time, answer, error}
        alt Agent 成功
            Eval->>Judge: llm_as_a_judge(question, truth, wf_answer)
            Judge-->>Eval: {relevance, correctness}
        end
        alt RAG 成功
            Eval->>Judge: llm_as_a_judge(question, truth, rag_answer)
            Judge-->>Eval: {relevance, correctness}
        end
        Eval->>Eval: sleep 1s (限流)
    end
    Eval->>Eval: 保存 results.json
```

**说明**: 评估框架的核心循环。对每个任务，分别运行 Agent 和 RAG，收集执行信息，然后使用 LLM-as-Judge 评估回答质量。
