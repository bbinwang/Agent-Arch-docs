# 8. 部署、运维与基础设施（Deployment, Ops & Infrastructure）

> 本章详细描述 Sirchmunk 的部署架构、Docker 配置、CI/CD 流水线、监控日志与备份方案。

## 8.0 部署架构总览

Sirchmunk 采用**单容器单进程**部署模式，所有组件（后端 API + 前端 WebUI）打包在一个 Docker 镜像中，通过单个端口（8584）对外提供服务。

## 8.2 Docker 多阶段构建详解

### 8.2.1 Dockerfile 结构

Sirchmunk 使用**多阶段构建**（Multi-stage Build），分为两个阶段：

```
Stage 1: frontend-builder（Node.js 构建前端）
    │
    ▼
Stage 2: runtime（Python 运行时 + 后端 + 前端产物）
```

### 8.2.2 Stage 1: 前端构建

```dockerfile
FROM node:23 AS frontend-builder

WORKDIR /build/web
COPY web/package.json web/package-lock.json* ./
RUN npm ci --prefer-offline

COPY web/ ./

ENV NEXT_BUILD_STATIC=true
ENV NEXT_PUBLIC_API_BASE=""
RUN npm run build
```

**关键配置**：
- `NEXT_BUILD_STATIC=true`：启用静态导出
- `NEXT_PUBLIC_API_BASE=""`：API 请求使用相对路径（单端口模式）
- 构建产物输出到 `/build/web/out`

### 8.2.3 Stage 2: Python 运行时

```dockerfile
FROM python:3.12-slim AS runtime

# 系统依赖
RUN apt-get update && apt-get install -y \
    build-essential curl git \
    poppler-utils pandoc tesseract-ocr ffmpeg \
    vim less procps net-tools htop

# 安装 ripgrep + ripgrep-all（架构感知）
# ...

# Python 依赖
COPY requirements/ requirements/
RUN pip install --no-cache-dir \
    -r requirements/core.txt \
    -r requirements/web.txt \
    -r requirements/mcp.txt

# 源码安装
COPY src/ src/
COPY pyproject.toml setup.py README.md ./
RUN pip install --no-cache-dir -e ".[mcp,web]"

# 前端产物
COPY --from=frontend-builder /build/web/out /app/web_static

# 预下载 embedding 模型
ENV EMBEDDING_CACHE_DIR=/app/.cache/models
RUN python -c "from sirchmunk.utils.embedding_util import EmbeddingUtil; \
    EmbeddingUtil.preload_model(cache_dir='/app/.cache/models')"

# 入口
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
EXPOSE 8584
ENTRYPOINT ["/entrypoint.sh"]
CMD ["sirchmunk", "web", "serve", "--host", "0.0.0.0", "--port", "8584"]
```

### 8.2.4 系统依赖说明

| 依赖 | 用途 |
|------|------|
| `poppler-utils` | PDF 文本提取 |
| `pandoc` | 文档格式转换 |
| `tesseract-ocr` | 图片 OCR |
| `ffmpeg` | 音视频处理 |
| `ripgrep` | 全文检索 |
| `ripgrep-all` | 跨格式全文检索 |
| `build-essential` | Python 包编译 |
| `procps/net-tools/htop` | 调试工具 |

### 8.2.5 架构感知的 rga 安装

```dockerfile
ARG TARGETARCH
RUN case "${TARGETARCH}" in \
    amd64) \
        # 下载 amd64 版本
        RGA_ARCH="x86_64-unknown-linux-musl" ;; \
    arm64) \
        # 下载 arm64 版本
        RGA_ARCH="aarch64-unknown-linux-gnu" ;; \
    *) echo "Unsupported architecture" && exit 1 ;; \
    esac
```

## 8.3 Docker Compose 配置详解

### 8.3.1 `docker-compose.yml`

```yaml
services:
  sirchmunk:
    image: ${SIRCHMUNK_IMAGE:-sirchmunk:latest}
    build:
      context: ..
      dockerfile: Dockerfile
    container_name: sirchmunk

      - "8584:8584"

      # - /path/to/sirchmunk_workspace:/data/sirchmunk

      - LLM_BASE_URL=${LLM_BASE_URL:-https://api.openai.com/v1}
```

| `LLM_API_KEY` | — | LLM API 密钥 |

## 8.4 Entrypoint 启动流程详解

### 8.4.1 `entrypoint.sh` 流程

```bash
#!/bin/bash
set -e

WORK_PATH="${SIRCHMUNK_WORK_PATH:-/data/sirchmunk}"

# 1. 创建目录结构
mkdir -p "$WORK_PATH"/{data,logs,.cache/models,.cache/knowledge,.cache/history,.cache/settings,.cache/web_static}

# 2. 复制前端静态资源（如果不存在）
if [ -d /app/web_static ] && [ ! -f "$WORK_PATH/.cache/web_static/index.html" ]; then
    cp -r /app/web_static/* "$WORK_PATH/.cache/web_static/"
fi

# 3. 生成默认 .env（如果不存在）
if [ ! -f "$WORK_PATH/.env" ]; then
    cp /app/config/env.example "$WORK_PATH/.env"
fi

# 4. 生成 MCP 客户端配置（如果不存在）
if [ ! -f "$WORK_PATH/mcp_config.json" ]; then
    cat > "$WORK_PATH/mcp_config.json" <<'MCPEOF'
{
  "mcpServers": {
    "sirchmunk": {
      "command": "sirchmunk",
      "args": ["mcp", "serve"],
      "env": {"SIRCHMUNK_SEARCH_PATHS": ""}
    }
  }
}
MCPEOF
fi

# 5. 应用环境变量覆盖到 .env
for var in LLM_BASE_URL LLM_API_KEY LLM_MODEL_NAME ...; do
    val="${!var}"
    if [ -n "$val" ]; then
        python3 -c "..."  # 安全替换
    fi
done

# 6. 执行 CMD
exec "$@"
```

### 8.4.2 启动流程说明

1. **目录结构初始化**：创建 data、logs、.cache 等必要目录
2. **前端资源复制**：将镜像内的静态资源复制到持久化卷（首次启动）
3. **配置文件生成**：生成默认 .env 和 mcp_config.json
4. **环境变量覆盖**：将 Docker 环境变量安全写入 .env 文件
5. **命令执行**：`exec "$@"` 替换 shell 进程，确保信号正确传递

### 8.4.3 .env 安全替换

使用 Python 脚本而非 sed 进行替换，避免特殊字符（`/`, `&`, `|`, `\`）导致的 sed 分隔符问题：

```python
python3 -c "
import sys, pathlib
key, val, p = sys.argv[1], sys.argv[2], pathlib.Path(sys.argv[3])
lines = p.read_text().splitlines(True) if p.exists() else []
found = False
out = []
for line in lines:
    if line.startswith(key + '='):
        out.append(key + '=' + val + '\n')
        found = True
    else:
        out.append(line)
if not found:
    out.append(key + '=' + val + '\n')
p.write_text(''.join(out))
" "$var" "$val" "$WORK_PATH/.env"
```

## 8.5 CI/CD 流水线

### 8.5.1 GitHub Actions: `docker-image.yaml`

**触发方式**：`workflow_dispatch`（手动触发）

**输入参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sirchmunk_branch` | `main` | 构建分支 |
| `image_type` | `cpu` | 镜像类型 |
| `sirchmunk_version` | 自动 | 版本号（空=自动读取） |
| `ubuntu_version` | `22.04` | Ubuntu 版本 |
| `python_version` | `3.12` | Python 版本 |
| `node_version` | `23` | Node.js 版本 |
| `mirror` | — | 镜像加速配置（cn/空） |

**构建步骤**：
1. Checkout 代码
2. 生成 Dockerfile（`build_image.py`）
3. Docker Buildx 构建
4. 推送到 ACR（Alibaba Cloud Container Registry）

### 8.5.2 `build_image.py` 构建脚本

**功能**：
- 读取 `version.py` 获取版本号
- 渲染 Dockerfile 模板
- 支持中国镜像加速（pip/npm/github proxy）
- 多架构构建（amd64/arm64）
- 多 Registry 推送

**用法**：
```bash
# 本地构建
python docker/build_image.py

# 仅生成 Dockerfile
python docker/build_image.py --dry_run 1

# 中国镜像加速
python docker/build_image.py --mirror cn

# 构建并推送
python docker/build_image.py --push
```

**镜像加速配置**（`--mirror cn`）：
```python
MIRROR_PROFILES = {
    "cn": {
        "docker_prefix": "docker.m.daocloud.io/library/",
        "pip_index_url": "https://mirrors.aliyun.com/pypi/simple/",
        "npm_registry": "https://registry.npmmirror.com",
        "github_proxy": "https://ghfast.top/",
    }
}
```

### 8.5.3 GitHub Actions: `publish.yaml`

**功能**：自动发布到 PyPI（Python Package Index）

**触发方式**：Release 发布事件

**步骤**：
1. Checkout 代码
2. 设置 Python 环境
3. 安装 build 工具
4. 构建 wheel 和 sdist
5. 上传到 PyPI

## 8.6 监控方案

### 8.6.1 MonitorTracker

**实现**：`api/components/monitor_tracker.py` → `MonitorTracker`

**采集的指标**：

| 类别 | 指标 | 来源 |
|------|------|------|
| CPU | 使用率、核心数、频率 | psutil |
| 内存 | 总量、已用、使用率 | psutil |
| 磁盘 | 总量、已用、使用率 | psutil |
| 网络 | 连接数 | psutil |
| 进程 | PID、内存、线程数 | psutil |
| 系统 | 运行时间 | psutil |
| 聊天 | 会话数、消息数、活跃会话 | DuckDB |
| 知识 | 簇数量、新增数 | KnowledgeStorage |
| LLM | 调用次数、token 用量 | LLMUsageTracker |

**健康评分算法**：
```python
# 基于 CPU、内存、磁盘使用率计算健康分数
score = 100 - max(cpu_pct, mem_pct, disk_pct) * 0.5
if score >= 90: status = "excellent"
elif score >= 70: status = "good"
elif score >= 50: status = "warning"
else: status = "critical"
```

### 8.6.2 LLMUsageTracker

**实现**：线程安全单例模式

```python
class LLMUsageTracker:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
        return cls._instance
```

**追踪的指标**：
- `total_calls`：总调用次数
- `total_input_tokens`：总输入 token
- `total_output_tokens`：总输出 token
- `total_tokens`：总 token
- `calls_by_model`：按模型分类统计
- `last_call_time`：最后调用时间
- `session_start`：会话开始时间

### 8.6.3 监控端点

| 端点 | 功能 |
|------|------|
| `GET /api/v1/monitor/overview` | 综合概览 |
| `GET /api/v1/monitor/system` | 系统指标 |
| `GET /api/v1/monitor/health` | 健康状态 |
| `GET /api/v1/monitor/chat` | 聊天活动 |

### 8.8.1 需要持久化的数据

| 数据 | 位置 | 备份策略 |
|------|------|---------|
| 环境配置 | `.env` | 卷挂载 |

**方案 1：卷挂载 + 宿主机备份**

**方案 2：DuckDB 导出**

```python
# 导出 DuckDB 数据
```

```python
# 导出所有知识簇
```
