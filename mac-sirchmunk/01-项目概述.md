# 1. 项目概述（Project Overview）

> 本章从宏观层面全面介绍 Sirchmunk 项目的目标、价值、技术栈、架构风格、功能特性与非功能性需求。

---

## 1.1 项目目标与核心价值主张

### 1.1.1 项目定位

**Sirchmunk** 是一个开源的 **Agentic Search & Self-Evolving Knowledge Base**（智能体搜索与自进化知识库）系统。其核心定位是：**让 AI Agent 能够直接与原始数据交互，无需昂贵的预索引管线，同时让知识能够随数据实时进化**。

项目由 **ModelScope 团队** 开发与维护，遵循 Apache 2.0 开源许可，旨在解决传统 RAG（Retrieval-Augmented Generation）系统的根本性缺陷。

### 1.1.2 核心价值主张

Sirchmunk 围绕三大核心价值构建：

**1. Embedding-Free（无嵌入）：数据最纯粹形态**

传统 RAG 系统需要将文档切分、生成向量嵌入、存入向量数据库，这一过程存在三大问题：
- **信息损失**：固定维度的向量无法完整保留原始文档的语义精度
- **计算昂贵**：大规模文档集的嵌入计算消耗大量 GPU/CPU 资源
- **更新滞后**：数据变化需要重新触发完整的 ETL 管线

Sirchmunk 绕过这一切，直接对原始文件进行检索，实现零信息损失。

**2. Self-Evolving（自进化）：活的索引**

数据是流，不是快照。Sirchmunk 的知识库会随着搜索和使用自动进化：
- 知识簇（KnowledgeCluster）自动合并、连接
- 语义边（Semantic Edge）动态刷新
- 元簇（Meta Cluster）自动检测
- 全局知识图谱定期更新

**3. Intelligence at Scale（规模化智能）**

通过 ripgrep-all 直接检索 + LLM 推理的混合策略，Sirchmunk 能够：
- 处理大规模本地代码仓库与文档集合
- 支持 100+ 文件格式（包括二进制格式）
- 保持极低的 RAM/CPU 消耗

### 1.1.3 解决的问题

| 问题 | 传统方案 | Sirchmunk 方案 |
|------|---------|---------------|
| 向量索引构建成本高 | 需要 GPU + 数小时 | 零预索引，即搜即用 |
| 数据更新导致索引过期 | 批量重建（小时/天级） | 实时反映数据变化 |
| 向量近似导致精度损失 | ANN 搜索不保证精确 | 确定性匹配 + 上下文推理 |
| 大规模数据资源消耗大 | 向量 DB 占用大量内存 | 原生 OS 文件系统 + rga |
| 知识静态不进化 | 检索结果不积累 | 知识图谱自进化 |

## 1.4 项目架构风格及设计理由

### 1.4.1 整体架构风格

Sirchmunk 采用 **分层架构 + 事件驱动 + 微内核（插件）** 的混合架构风格：

```
┌─────────────────────────────────────────────────────┐
│                 Presentation Layer                   │
│         (Next.js WebUI / CLI / MCP Client)          │
├─────────────────────────────────────────────────────┤
│                    API Layer                         │
│    (FastAPI Routes / WebSocket / REST / MCP)        │
├─────────────────────────────────────────────────────┤
│                  Agent Layer                         │
│        (ReAct Agent / Tool Registry)                │
├─────────────────────────────────────────────────────┤
│                 Core Engine Layer                    │
│   (AgenticSearch / KnowledgeBase / Evolver)         │
├─────────────────────────────────────────────────────┤
│                Retrieval Layer                       │
│  (GrepRetriever / TreeIndexer / SummaryIndex)       │
├─────────────────────────────────────────────────────┤
│                 Storage Layer                        │
│      (DuckDB / FileSystem / KnowledgeStorage)       │
└─────────────────────────────────────────────────────┘
```

### 1.4.2 设计理由

**1. 分层架构（Layered Architecture）**

- **理由**：清晰的职责分离，每层只依赖下层，便于独立测试与替换
- **体现**：API 层 → Agent 层 → Engine 层 → Retrieval 层 → Storage 层

**2. ReAct Agent 模式（Reasoning + Acting）**

- **理由**：将搜索建模为迭代推理-行动循环，LLM 自主决定检索策略
- **优势**：比固定管线更灵活，能根据查询复杂度动态调整检索深度
- **文件**：`agentic/react_agent.py`

**3. 工具注册中心（Tool Registry / 微内核）**

- **理由**：检索工具可插拔，新增工具只需实现 `BaseTool` 接口并注册
- **体现**：`agentic/tools.py` 中的 `ToolRegistry` 类
- **当前工具**：`keyword_search`、`deep_file_read`、`knowledge_query`、`web_search`

**4. 事件驱动日志（Event-Driven Logging）**

- **理由**：搜索过程中的关键事件通过异步回调实时推送到前端
- **体现**：`LogCallback` 类型 + `create_logger()` 工厂

**5. 自进化知识（Self-Evolving Knowledge）**

- **理由**：知识不是一次性编译的静态产物，而是随使用不断精炼的活体
- **体现**：`scheduler/evolver.py` 中的 `KnowledgeEvolver`

### 1.4.3 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 检索方式 | ripgrep-all 而非向量 DB | 零索引成本、实时性、确定性 |
| Agent 范式 | ReAct 而非固定管线 | 灵活适应不同复杂度查询 |
| 知识表示 | KnowledgeCluster 图谱 | 支持推理与进化 |
| 存储引擎 | DuckDB 而非 SQLite/PG | 嵌入式、OLAP 优化、零运维 |
| 前端框架 | Next.js 而非 Vue/Angular | SSR/静态导出、React 生态 |
| 协议 | MCP + REST + WebSocket | 兼顾 Agent 集成与实时交互 |

## 1.5 关键功能特性详解

### 1.5.1 特性 1：Embedding-Free 即时搜索

**功能描述**：用户将文件放入工作目录后立即可以搜索，无需任何预处理。

**技术实现**：
- 基于 `ripgrep-all` (rga) 实现跨格式全文检索
- 支持正则/字面量/布尔逻辑（AND/OR/NOT）
- 支持文件类型过滤、深度限制、包含/排除模式
- 结果按相关性排序并返回上下文片段

**涉及模块**：`retrieve/text_retriever.py` → `GrepRetriever`

### 1.5.2 特性 2：ReAct Agentic Search

**功能描述**：LLM 驱动的迭代搜索，自动决定搜索策略。

**工作流程**：
1. 用户输入查询
2. LLM 分析查询，提取关键词
3. Agent 进入 ReAct 循环：
   - **Reasoning**：LLM 思考需要什么信息
   - **Acting**：选择并调用检索工具
   - **Observing**：分析工具返回结果
   - 循环直到找到答案或达到限制
4. 综合所有证据生成最终回答

**涉及模块**：`agentic/react_agent.py` → `ReActSearchAgent`

### 1.5.3 特性 3：蒙特卡洛证据采样

**功能描述**：使用随机化策略从大规模文档中高效采样证据。

**技术实现**：
- 基于 ROI（Region of Interest）的采样
- 多轮迭代：定位 → 读取 → 验证 → 扩展
- 自适应采样深度（根据文件大小和结构）

**涉及模块**：`learnings/evidence_processor.py` → `MonteCarloEvidenceSampling`

### 1.5.4 特性 4：自进化知识库

**功能描述**：搜索过程中自动构建和进化知识图谱。

**四个进化阶段**：
1. **Connect & Merge**：新知识簇达到阈值时自动连接与合并
2. **Edge Refresh**：定期刷新语义边权重
3. **Meta Cluster Detection**：使用 Leiden 算法检测元簇
4. **Global Update**：全局知识图谱更新

**涉及模块**：`scheduler/evolver.py` → `KnowledgeEvolver`

### 1.5.5 特性 5：文档树索引

**功能描述**：为长文档构建层级结构索引，支持 LLM 导航。

**技术实现**：
- 多层 TOC 提取（pypdf → pdfminer → 标题模式 → LLM）
- 自适应深度（根据文档大小）
- 结构化内容检测（表格/数值密度）

**涉及模块**：`learnings/tree_indexer.py` + `learnings/toc_extractor.py`

### 1.5.6 特性 6：MCP Server 集成

**功能描述**：将 Sirchmunk 搜索能力暴露为 MCP 工具，供 AI Agent 调用。

**技术实现**：
- 基于 FastMCP 实现 MCP 协议
- 暴露 `sirchmunk_search` 和 `sirchat` 两个工具
- 支持 stdio 和 HTTP 两种传输模式

**涉及模块**：`src/sirchmunk_mcp/` 全部

## 1.6 非功能性需求

### 1.6.1 性能（Performance）

| 指标 | 目标 | 实现方式 |
|------|------|---------|
| 首次搜索延迟 | < 2s | ripgrep-all 直接检索，无索引构建 |
| 单次 LLM 调用 | < 30s | 流式输出 + 超时控制 |
| 完整 Agent 搜索 | < 120s | max_loops=10, token_budget 限制 |
| 并发搜索 | 支持 | asyncio + Semaphore 并发控制 |
| 大文件处理 | 支持 GB 级 | 流式读取 + 采样策略 |

### 1.6.2 扩展性（Scalability）

| 维度 | 策略 |
|------|------|
| 数据规模 | 直接检索文件系统，无索引大小限制 |
| 并发用户 | uvicorn workers 水平扩展 |
| 工具扩展 | ToolRegistry 插件式注册 |
| 存储扩展 | DuckDB 支持 TB 级分析 |
| 前端扩展 | Next.js 静态导出 + CDN |

### 1.6.3 安全性（Security）

| 层面 | 措施 |
|------|------|
| 认证 | Bearer Token (SIRCHMUNK_API_TOKEN) |
| 路径安全 | 白名单 + 符号链接检测 + 路径遍历防护 |
| 文件名安全 | sanitize_filename 过滤危险字符 |
| HTTP 安全头 | CSP / HSTS / X-Frame-Options 等 |
| 限流 | 内存 Token Bucket（per-IP） |
| 审计日志 | JSON-Lines 格式路径访问审计 |
| Prompt 注入 | 检测与拦截（预留接口） |

### 1.6.4 可用性（Availability）

| 指标 | 策略 |
|------|------|
| 服务可用 | Docker restart: unless-stopped |
| 健康检查 | `/health` 端点 |
| 错误恢复 | LLM 调用自动重试（指数退避） |
| 子进程隔离 | 文档提取在独立进程中执行，崩溃不影响主服务 |
| 优雅降级 | rga 失败时回退到 SummaryIndex |

### 1.6.5 可维护性（Maintainability）

| 方面 | 措施 |
|------|------|
| 代码结构 | 模块化分层，单一职责 |
| 类型注解 | 全代码 Python type hints |
| 文档字符串 | 所有公共函数均有 docstring |
| 配置管理 | 环境变量 + .env 统一配置 |
| 日志 | Loguru 结构化日志 + 异步回调 |
| 知识健康检查 | Lint 模块自动检测异常知识簇 |

## 1.8 本章小结

Sirchmunk 是一个创新的 Agentic Search 系统，通过以下核心理念重新定义了数据检索：

1. **无嵌入**：绕过昂贵的向量索引，直接检索原始数据
2. **ReAgent 驱动**：LLM 自主决策检索策略
3. **自进化**：知识图谱随使用自动精炼
4. **零配置**：即丢即搜，无需预处理
5. **开放协议**：MCP + REST + WebSocket 全面集成

这些特性使 Sirchmunk 在 RAG 生态中独树一帜，特别适合需要实时性、确定性和自适应能力的 AI Agent 应用场景。
