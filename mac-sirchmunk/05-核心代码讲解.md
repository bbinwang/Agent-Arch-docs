## 5.1 `search.py` — AgenticSearch 核心搜索引擎

### 5.1.1 文件概览

| 属性 | 值 |
|------|-----|
| 行数 | ~7,900 行（项目最大单文件） |
| 核心类 | `AgenticSearch(BaseSearch)` |
| 依赖模块 | learnings, retrieve, llm, schema, scheduler, utils |

### 5.1.2 类定义：`AgenticSearch`

```python
class AgenticSearch(BaseSearch):
    def __init__(
        self,
        paths: Union[str, Path, List[str], List[Path]],
        llm: OpenAIChat = None,
        enable_dir_scan: bool = True,
        log_callback: LogCallback = None,
    ):
```

**参数说明**：
- `paths`：搜索路径列表（文件或目录）
- `llm`：LLM 客户端实例（可选，默认从环境变量创建）
- `enable_dir_scan`：是否启用目录扫描
- `log_callback`：异步日志回调函数

**初始化逻辑**：
1. 规范化搜索路径（`Path.resolve()`）
2. 创建或复用 `OpenAIChat` 实例
3. 初始化 `GrepRetriever`（绑定工作路径）
4. 初始化 `KnowledgeBase`（绑定 LLM 和元数据）
5. 初始化 `KnowledgeEvolver`
6. 初始化 `SearchContext`（用于遥测）

### 5.1.3 核心方法：`search()`

```python
async def search(
    self,
    query: str,
    mode: Literal["FAST", "DEEP"] = "FAST",
    max_loops: int = 10,
    max_token_budget: int = 64000,
    return_context: bool = False,
    images: Optional[List[str]] = None,
    include: Optional[List[str]] = None,
    exclude: Optional[List[str]] = None,
) -> Union[str, Tuple[str, SearchContext]]:
```

**参数说明**：
- `query`：用户查询文本
- `mode`：搜索模式（`FAST` 快速 / `DEEP` 深度）
- `max_loops`：最大 ReAct 循环次数
- `max_token_budget`：LLM token 预算上限
- `return_context`：是否返回 SearchContext（遥测数据）
- `images`：图片 URL 列表（预留）
- `include`/`exclude`：文件包含/排除模式

**核心逻辑**：
1. **意图检测**：调用 `doc_qa.detect_doc_intent()` 判断是否为文档级操作
2. **文档 QA 分支**：如果意图检测通过，走 `analyse_documents()` 直读管线
3. **关键词提取**：使用 LLM 从查询中提取结构化关键词
4. **ReAct Agent 创建**：实例化 `ReActSearchAgent`，传入 `ToolRegistry`
5. **执行搜索**：调用 `agent.run(query, initial_keywords=keywords)`
6. **知识编译**：调用 `kb.compile()` 生成 KnowledgeCluster
7. **知识进化**：调用 `evolver.step(cluster)` 触发进化
8. **结果返回**：返回答案文本（或 + SearchContext）

**异常处理**：
- LLM 调用失败：内部重试（`OpenAIChat._retry_with_backoff()`）
- 工具执行异常：捕获并记录日志，继续循环
- 预算耗尽：强制合成答案

**潜在问题**：
1. **单文件过长**（~7900 行）：违反单一职责原则，难以维护
2. **模式切换不完整**：`mode="DEEP"` 分支逻辑尚未完全实现
3. **硬编码参数**：`max_loops`、`max_token_budget` 等参数散布在多处

**改进建议**：
1. 拆分 `search.py` 为多个子模块（意图检测、关键词提取、管线协调）
2. 实现完整的 `DEEP` 模式逻辑（多轮蒙特卡洛采样）
3. 提取搜索配置为 `SearchConfig` dataclass

### 5.1.4 其他关键方法

| 方法 | 功能 |
|------|------|
| `compile()` | 知识编译入口，调用 `KnowledgeBase.compile()` |
| `detect_doc_intent()` | 代理到 `doc_qa.detect_doc_intent()` |
| `analyse_documents()` | 代理到 `doc_qa.analyse_documents()` |
| `get_search_paths()` | 返回规范化后的搜索路径列表 |

- `tool_registry`：工具注册中心

### 5.2.3 核心方法：`run()`

```python
async def run(
    self,
    query: str,
    images: Optional[List[str]] = None,
    initial_keywords: Optional[List[str]] = None,
) -> Tuple[str, SearchContext]:
```

**核心逻辑**：
1. 创建 `SearchContext`（token 预算、循环计数、文件去重）
2. 构建系统 Prompt（包含工具描述和上下文状态）
3. 构建用户消息（查询 + 可选图片标记）
4. 如果有初始关键词，预执行 `keyword_search` 并注入结果
5. 进入主循环：
   - 调用 LLM 推理
   - 提取 `<ANSWER>` 标签
   - 解析工具调用
   - 执行工具并获取结果
   - 更新消息历史
   - 检查终止条件
6. 如果循环退出时未找到答案，强制合成
7. 返回 `(final_answer, context)`

**设计亮点**：
- **初始关键词预执行**：减少首次循环开销
- **nudge 机制**：LLM 不遵从指令时的优雅恢复
- **结果截断**：防止单次工具结果撑爆预算
- **强制合成**：保证即使预算耗尽也有输出

### 5.2.4 辅助函数

| 函数 | 功能 |
|------|------|
| `_extract_answer(text)` | 正则提取 `<ANSWER>...</ANSWER>` |
| `_parse_tool_call(text, tools)` | 多策略工具调用解析 |
| `_build_tool_descriptions(registry)` | 生成 LLM 可读的工具描述 |

### 5.2.5 潜在问题与改进

**问题**：
1. `_parse_tool_call` 的正则策略可能误匹配非工具调用文本
2. 强制合成阶段可能产生低质量答案（预算耗尽时证据不足）

**改进**：
1. 使用结构化输出（JSON Mode / Function Calling）替代自由文本解析
2. 在合成阶段注入所有已收集证据的摘要

### 5.3.2 抽象基类：`BaseTool`

```python
class BaseTool(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """Tool name (must be unique within a ToolRegistry)."""

    @abstractmethod
    def get_schema(self) -> Dict[str, Any]:
        """Return OpenAI function-calling schema for this tool."""

    @abstractmethod
    async def execute(
        self,
        context: SearchContext,
        **kwargs,
    ) -> Tuple[str, Dict[str, Any]]:
        """Execute the tool."""
```

**设计说明**：
- `name`：唯一标识符，LLM 通过此名称调用工具
- `get_schema()`：返回 OpenAI Function Calling 兼容的 JSON Schema
- `execute()`：执行工具并返回 `(result_text, metadata)`

### 5.3.3 工具注册中心：`ToolRegistry`

```python
class ToolRegistry:
    def __init__(self):
        self._tools: Dict[str, BaseTool] = {}

    def register(self, tool: BaseTool) -> None:
        """Register a tool instance."""
        if tool.name in self._tools:
            raise ValueError(f"Tool '{tool.name}' already registered")
        self._tools[tool.name] = tool

    async def execute(
        self,
        tool_name: str,
        context: SearchContext,
        **kwargs,
    ) -> Tuple[str, Dict[str, Any]]:
        """Execute a tool by name."""
        if tool_name not in self._tools:
            return f"Error: Unknown tool '{tool_name}'", {}
        return await self._tools[tool_name].execute(context, **kwargs)

    def get_all_schemas(self) -> List[Dict[str, Any]]:
        """Get all tool schemas for LLM prompt."""
        return [tool.get_schema() for tool in self._tools.values()]

    @property
    def tool_names(self) -> List[str]:
        """List of registered tool names."""
        return list(self._tools.keys())
```

**设计亮点**：
- 注册时检查名称唯一性
- `execute()` 统一入口，工具实现细节对外透明
- `get_all_schemas()` 动态生成工具描述

### 5.4.1 文件概览

### 5.4.2 核心方法：`retrieve()`

```python
async def retrieve(
    self,
    terms: Union[str, List[str]],
    path: Union[str, Path, List[str], List[Path], None] = None,
    logic: Literal["and", "or", "not"] = "or",
    *,
    case_sensitive: bool = False,
    whole_word: bool = False,
    literal: bool = False,
    regex: bool = True,
    max_depth: Optional[int] = None,
    include: Optional[List[str]] = None,
    exclude: Optional[List[str]] = None,
    file_type: Optional[str] = None,
    invert_match: bool = False,
    count_only: bool = False,
    line_number: bool = True,
    with_filename: bool = True,
    max_results: Optional[int] = None,
    context: Optional[int] = None,
    output_mode: Literal["content", "count", "files_with_matches", "json"] = "json",
) -> Dict[str, Any]:
```

**参数说明**（关键）：
- `terms`：搜索词（字符串或列表）
- `logic`：多词布尔逻辑（`and`/`or`/`not`）
- `regex`/`literal`：正则模式 vs 字面量模式
- `include`/`exclude`：glob 模式过滤
- `max_depth`：目录深度限制
- `output_mode`：输出格式（推荐 `json` 便于解析）

**核心逻辑**：
1. 构建 rga 命令行参数列表
2. 使用 `asyncio.create_subprocess_exec()` 异步执行
3. 通过 `RGA_SEMAPHORE` 控制并发（默认 5）
4. 解析 JSON 输出为结构化结果
5. 返回包含 `matches`、`file_path`、`line_number` 的字典

**安全设计**：
- `shell=False`：防止 shell 注入
- 参数列表而非字符串拼接
- 路径验证（`is_path_allowed()`）

### 5.4.3 潜在问题与改进

**问题**：
1. 大量结果时内存占用高（全部加载到内存）
2. 缺少搜索结果的相关性排序
3. rga 二进制路径硬编码为 `rga`

**改进**：
1. 使用生成器逐行读取结果（流式处理）
2. 实现基于 TF-IDF 或 BM25 的结果排序
3. 通过配置指定 rga 路径

## 5.19 本章小结

本章对 Sirchmunk 的 18 个核心文件进行了逐函数走读：
