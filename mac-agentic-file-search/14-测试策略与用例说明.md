## 1. 测试策略概述

本文档详细阐述 FsExplorer 项目的测试体系，包括测试架构、Mock 策略、用例设计模式、CI 集成以及覆盖率目标。当前测试体系包含 **10 个测试文件 + 1 个 conftest**，共计约 **104 个测试函数**，覆盖 Agent 核心、文件系统、搜索检索、索引管道、API 端点和 CLI 命令等关键模块。

### 1.1 测试原则

| 原则 | 说明 | 实现方式 |
|------|------|----------|
| **独立性** | 每个测试独立运行，无共享可变状态 | `setup_method`/`teardown_method` 清理全局状态 |
| **确定性** | 相同输入始终产生相同输出 | Mock 外部依赖（Gemini API、文件系统） |
| **可重复** | 测试可在任何环境重复执行 | `tmp_path` 临时目录，不依赖外部服务 |
| **快速反馈** | 单元测试秒级完成 | 避免真实 API 调用，使用内存数据库 |
| **可读性** | 测试名称清晰表达意图 | 描述性函数名 + 隐式 Given-When-Then 结构 |

### 1.2 测试技术栈

| 工具 | 版本 | 用途 |
|------|------|------|
| pytest | 9.0.2+ | 测试框架 |
| pytest-asyncio | 1.3.0+ | 异步测试支持 |
| typer.testing.CliRunner | - | CLI 命令测试 |
| fastapi.testclient.TestClient | - | REST API 测试 |
| unittest.mock | 标准库 | Mock/Stub/Monkeypatch |
| tmp_path | pytest 内置 | 临时文件/数据库 |

## 2. 测试金字塔结构

FsExplorer 采用经典 **测试金字塔** 模型，从底向上分为三层：

```
              /\
             /  \        E2E 测试 (1 个)
            /----\       ↑ 完整工作流验证
           /      \
          /--------\     集成测试 (~34 个)
         /          \    ↑ 模块间交互验证
        /------------\
       /              \   单元测试 (~69 个)
      /----------------\  ↑ 单一函数/类验证
     /__________________\
```

### 2.1 各层测试分布

| 层级 | 测试数量 | 占比 | 测试文件 | 执行时间目标 |
|------|----------|------|----------|--------------|
| **单元测试** | ~69 | 66% | test_agent, test_fs, test_models, test_search, test_embeddings, test_exploration_trace | < 5 秒 |
| **集成测试** | ~34 | 33% | test_indexing, test_server_search, test_cli_indexing | < 30 秒 |
| **E2E 测试** | ~1 | 1% | test_e2e | < 60 秒 |

### 2.2 金字塔失衡分析

当前测试体系存在 **E2E 层薄弱** 的问题：

| 问题 | 影响 | 改进方向 |
|------|------|----------|
| E2E 仅 1 个测试 | 端到端流程覆盖不足 | 增加多场景 E2E（索引+查询、Agentic 探索、人机交互） |
| 无参数化测试 | 相似场景重复代码多 | 引入 `@pytest.mark.parametrize` |
| 无性能测试 | 无法检测性能退化 | 增加基准测试（benchmark） |

## 3. 测试架构设计

### 3.1 conftest.py 的 MockGenAIClient 设计

`conftest.py` 是整个测试体系的基石，提供 **三级 Mock 类层次** 替代真实的 Google GenAI 客户端：

```
MockGenAIClient          # 顶层客户端（替代 google.genai.Client）
  └── MockAio            # 异步接口属性 (.aio)
        └── MockModels   # 模型接口属性 (.models)
              └── generate_content()  # 返回 GenerateContentResponse
```

#### 3.1.1 MockGenAIClient 实现

```python
class MockGenAIClient:
    """模拟 google.genai.Client，避免真实 API 调用"""

    def __init__(self, api_key=None, http_options=None):
        # 忽略所有参数，无需真实连接
        self.aio = MockAio()

class MockAio:
    def __init__(self):
        self.models = MockModels()

class MockModels:
    def generate_content(self, model, contents, config):
        # 构造固定的 StopAction 响应
        action = StopAction(
            reason="Mock response",
            final_result="this is a final result"
        )
        return GenerateContentResponse(
            candidates=[Candidate(
                content=Content(parts=[Part(text=action.model_dump_json())])
            )],
            usage_metadata=GenerateContentResponseUsageMetadata(
                prompt_token_count=100,
                candidates_token_count=50,
                total_token_count=150
            )
        )
```

#### 3.1.2 为什么需要 Mock

| 原因 | 说明 |
|------|------|
| **避免 API 调用** | Gemini API 需要网络连接和真实 API Key，CI 环境不可用 |
| **确定性测试** | 真实 LLM 输出不确定，无法断言具体值 |
| **成本控制** | 104 个测试若全部调用真实 API，每次 CI 成本高昂 |
| **速度** | Mock 响应微秒级，真实 API 秒级 |
| **隔离性** | 测试聚焦被测逻辑，不受外部服务状态影响 |

#### 3.1.3 Mock 注入方式

```python
# 方式 1：直接替换实例属性
agent = FsExplorerAgent(api_key="test")
agent._client = MockGenAIClient(api_key="test")

# 方式 2：环境变量注入
@patch.dict(os.environ, {"GOOGLE_API_KEY": "test-api-key"})
def test_something():
    agent = FsExplorerAgent()  # 从环境变量读取 Key
```

### 3.2 全局状态管理

测试中需要清理的全局状态：

| 全局状态 | 清理方式 | 使用场景 |
|----------|----------|----------|
| `_DOCUMENT_CACHE` | `clear_document_cache()` | test_fs.py 的 setup_method |
| `_INDEX_CONTEXT` | `clear_index_context()` | test_agent.py 的 teardown |
| `_ENABLE_SEMANTIC` / `_ENABLE_METADATA` | `set_search_flags()` | test_agent.py 的 TestSearchFlags |
| `_FIELD_CATALOG_SHOWN` | 重置为 False | test_search.py |

## 5. 集成测试策略

### 5.1 test_e2e.py — 完整工作流测试

E2E 测试使用 `WorkflowTestRunner` 运行完整的探索工作流：

```python
@pytest.mark.asyncio
@pytest.mark.skipif(
    condition=os.getenv("GOOGLE_API_KEY") is None,
    reason="需要真实 API Key"
)
async def test_e2e():
    """端到端工作流测试"""
    # Given: 配置工作流
    workflow = FsExplorerWorkflow(timeout=300)
    agent = get_agent()
    agent._client = MockGenAIClient(api_key="test")

    # When: 运行工作流
    events = []
    async for event in workflow.run(
        task="find python file for file system operations",
        folder="data/test_acquisition/"
    ):
        events.append(event)

    # Then: 验证结果
    end_event = events[-1]
    assert isinstance(end_event, ExplorationEndEvent)
    assert end_event.error is None
    assert end_event.final_result is not None
    assert len(events) > 1
    assert any(isinstance(e, (ToolCallEvent, GoDeeperEvent)) for e in events)
```

## 6. Mock 策略详解

### 6.1 Mock 对象总览

| 被 Mock 对象 | Mock 方式 | 使用文件 | 目的 |
|-------------|----------|----------|------|
| `google.genai.Client` | `MockGenAIClient` 类 | conftest.py → test_agent.py | 避免 Gemini API 调用 |
| Embedding 客户端 | `_FakeClient/_FakeModels` 局部类 | test_embeddings, test_search, test_indexing | 避免 Embedding API 调用 |
| `parse_file` (Docling) | `monkeypatch.setattr` 为 `Path.read_text` | test_search, test_indexing, test_server_search, test_cli_indexing | 避免 CPU 密集型文档解析 |
| `auto_discover_profile` | `monkeypatch.setattr` | test_indexing | 避免 Schema 发现 API 调用 |
| `_extract_langextract_metadata` | `monkeypatch.setattr` | test_indexing | 避免 langextract API 调用 |
| `_get_genai_client` | `patch` 上下文管理器 | test_indexing | 避免 GenAI 客户端创建 |
| `run_workflow` (CLI) | `monkeypatch.setattr` 为 `fake_run_workflow` | test_cli_indexing | 避免运行真实工作流 |
| `IndexingPipeline` (CLI) | `monkeypatch.setattr` 为 `FakePipeline` | test_cli_indexing | 避免真实索引构建 |
| `os.environ` | `patch.dict` | test_agent, test_embeddings | 注入测试环境变量 |
