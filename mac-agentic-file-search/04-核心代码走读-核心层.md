## 1. agent.py (663 行)

agent.py 是系统的"大脑"，负责与 Gemini LLM 交互、管理工具注册、执行工具调用，并追踪 Token 消耗。

### 1.1 TokenUsage 数据类

```python
@dataclass
class TokenUsage:
    prompt_tokens: int = 0
    completion_tokens: int = 0
    total_tokens: int = 0
    api_calls: int = 0
    tool_result_chars: int = 0
    documents_parsed: int = 0
    documents_scanned: int = 0
```

**功能**：跨会话追踪 Token 使用量、API 调用次数、文档处理统计和成本估算。

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `prompt_tokens` | int | 累计输入 Token 数 |
| `completion_tokens` | int | 累计输出 Token 数 |
| `total_tokens` | int | 累计总 Token 数（= prompt + completion） |
| `api_calls` | int | API 调用次数 |
| `tool_result_chars` | int | 工具返回结果的总字符数 |
| `documents_parsed` | int | 解析的文档数 |
| `documents_scanned` | int | 扫描的文档数 |

**Gemini Flash 定价常量**：

```python
# Gemini Flash pricing (per million tokens)
GEMINI_FLASH_INPUT_COST_PER_MILLION = 0.075
GEMINI_FLASH_OUTPUT_COST_PER_MILLION = 0.30
```

这是 Google Gemini 3 Flash Preview 的官方定价（每百万 Token）：
- 输入：$0.075 / million tokens
- 输出：$0.30 / million tokens

#### add_api_call()

```python
def add_api_call(self, prompt_tokens: int, completion_tokens: int) -> None:
    """Record token usage from an API call."""
    self.prompt_tokens += prompt_tokens
    self.completion_tokens += completion_tokens
    self.total_tokens += prompt_tokens + completion_tokens
    self.api_calls += 1
```

**功能**：记录一次 API 调用的 Token 消耗。

**参数**：
- `prompt_tokens`: 本次调用的输入 Token 数
- `completion_tokens`: 本次调用的输出 Token 数

**核心逻辑**：
- 累加到对应计数器
- 自动计算 total_tokens
- api_calls 自增

#### add_tool_result()

```python
def add_tool_result(self, result: str, tool_name: str) -> None:
    """Record metrics from a tool execution."""
    self.tool_result_chars += len(result)
    if tool_name == "parse_file":
        self.documents_parsed += 1
    elif tool_name == "scan_folder":
        self.documents_scanned += result.count("│ [")
    elif tool_name == "preview_file":
        self.documents_parsed += 1
```

**功能**：记录工具执行的统计指标。

**参数**：
- `result`: 工具返回的字符串结果
- `tool_name`: 工具名称

**核心逻辑**：
- 累加 `tool_result_chars`（结果字符串长度）
- 根据工具类型更新文档计数
- `scan_folder` 特殊处理：通过计数 `"│ ["` 标记来统计扫描到的文档数（依赖输出格式）

**潜在问题**：`scan_folder` 的文档计数依赖输出格式的特定字符串，格式变化会导致计数不准。更稳健的做法是在 scan_folder 返回结果中显式包含文档数量。

#### _calculate_cost()

```python
def _calculate_cost(self) -> tuple[float, float, float]:
    """Calculate estimated costs based on Gemini Flash pricing."""
    input_cost = (self.prompt_tokens / 1_000_000) * GEMINI_FLASH_INPUT_COST_PER_MILLION
    output_cost = (self.completion_tokens / 1_000_000) * GEMINI_FLASH_OUTPUT_COST_PER_MILLION
    return input_cost, output_cost, input_cost + output_cost
```

**返回值**：`(input_cost, output_cost, total_cost)` 三元组

**成本公式**：
```
input_cost  = prompt_tokens / 1,000,000 × $0.075
output_cost = completion_tokens / 1,000,000 × $0.30
total_cost  = input_cost + output_cost
```

### 1.7 _get_index_storage_and_corpus()

```python
def _get_index_storage_and_corpus() -> tuple[DuckDBStorage | None, str | None, str | None]:
    if _INDEX_CONTEXT is None:
        return None, None, "Index context is not configured. Re-run with `--use-index`."
    storage = DuckDBStorage(_INDEX_CONTEXT.db_path)
    corpus_id = storage.get_corpus_id(_INDEX_CONTEXT.root_folder)
    if corpus_id is None:
        return None, None, f"No index found for folder {_INDEX_CONTEXT.root_folder}. ..."
    return storage, corpus_id, None
```

**功能**：索引工具的统一入口，获取存储和语料库 ID。

**核心逻辑**：

4. 返回结果或错误信息

**设计模式**：工厂模式 + 错误元组返回（类似 Go 风格错误处理）。

**潜在问题**：每次调用都创建新的 DuckDBStorage 实例，频繁调用时性能开销较大。

#### take_action()

```python
async def take_action(self) -> tuple[Action, ActionType] | None:
    """
    Request the next action from the AI model.

    Sends the current conversation history to Gemini and receives
    a structured JSON response indicating the next action to take.

    Returns:
        A tuple of (Action, ActionType) if successful, None otherwise.
    """
    response = await self._client.aio.models.generate_content(
        model="gemini-3-flash-preview",
        contents=self._chat_history,
        config={
            "system_instruction": _build_system_prompt(_ENABLE_SEMANTIC, _ENABLE_METADATA),
            "response_mime_type": "application/json",
            "response_schema": Action,
        },
    )

    # Track token usage from response metadata
    if response.usage_metadata:
        self.token_usage.add_api_call(
            prompt_tokens=response.usage_metadata.prompt_token_count or 0,
            completion_tokens=response.usage_metadata.candidates_token_count or 0,
        )

    if response.candidates is not None:
        if response.candidates[0].content is not None:
            self._chat_history.append(response.candidates[0].content)
        if response.text is not None:
            action = Action.model_validate_json(response.text)
            if action.to_action_type() == "toolcall":
                toolcall = cast(ToolCallAction, action.action)
                self.call_tool(
                    tool_name=toolcall.tool_name,
                    tool_input=toolcall.to_fn_args(),
                )
            return action, action.to_action_type()

    return None
```

**功能**：请求 AI 模型执行下一步动作。

**返回值**：`(Action, ActionType)` 元组，或 None（失败时）。

**核心逻辑流程**：

```
1. 调用 Gemini API（异步）
   - 模型：gemini-3-flash-preview
   - 内容：完整聊天历史
   - 配置：系统提示 + JSON 响应 + Action schema

2. 追踪 Token 使用量

3. 处理响应：
   - 将模型回复添加到聊天历史
   - 解析 JSON 为 Action 对象
   - 如果是 toolcall，自动执行工具（调用 call_tool）

4. 返回 (action, action_type)
```

**关键设计决策**：
- **自动执行工具**：toolcall 动作会在返回前自动执行，将结果加入聊天历史
- **聊天历史累积**：所有消息（用户、助手、工具结果）都累积在 `_chat_history` 中

**潜在问题**：
- 工具自动执行意味着 take_action() 有副作用
- 长时间运行的 Agent 会累积大量历史，可能超出上下文窗口

#### call_tool()

```python
def call_tool(self, tool_name: Tools, tool_input: dict[str, Any]) -> None:
    """
    Execute a tool and add the result to the conversation history.

    Args:
        tool_name: Name of the tool to execute.
        tool_input: Dictionary of arguments to pass to the tool.
    """
    try:
        result = TOOLS[tool_name](**tool_input)
    except Exception as e:
        result = (
            f"An error occurred while calling tool {tool_name} "
           f"with {tool_input}: {e}"
        )

    # Track tool result sizes
    self.token_usage.add_tool_result(result, tool_name)

    self._chat_history.append(
        Content(
            role="user",
            parts=[Part.from_text(text=f"Tool result for {tool_name}:\n\n{result}")],
        )
    )
```

**功能**：执行工具并将结果添加到对话历史。

**参数**：
- `tool_name`: 工具名称（必须是 TOOLS 的键）
- `tool_input`: 工具参数字典

**核心逻辑**：
1. 从 TOOLS 字典查找并调用工具
2. 异常处理：捕获所有异常，转换为错误消息字符串
3. 追踪工具结果统计
4. 将结果包装为 "Tool result for {name}" 格式添加到聊天历史

**设计模式**：
- 命令模式（通过名称查找执行）

### 2.5 _handle_action_result()

```python
def _handle_action_result(
    action: Action,
    action_type: str,
    ctx: Context[WorkflowState],
) -> WorkflowEvent:
    """
    Convert an action result into the appropriate workflow event.

    Args:
        action: The action returned by the agent
        action_type: The type of action ("godeeper", "toolcall", "askhuman", "stop")
        ctx: The workflow context for state updates and event streaming

    Returns:
        The appropriate workflow event based on the action type
    """
    if action_type == "godeeper":
        godeeper = cast(GoDeeperAction, action.action)
        event = GoDeeperEvent(directory=godeeper.directory, reason=action.reason)
        ctx.write_event_to_stream(event)
        return event
    elif action_type == "toolcall":
        toolcall = cast(ToolCallAction, action.action)
        event = ToolCallEvent(
            tool_name=toolcall.tool_name,
            tool_input=toolcall.to_fn_args(),
            reason=action.reason,
        )
        ctx.write_event_to_stream(event)
        return event
    elif action_type == "askhuman":
        askhuman = cast(AskHumanAction, action.action)
        return AskHumanEvent(question=askhuman.question, reason=action.reason)
    else:  # stop
        stopaction = cast(StopAction, action.action)
        return ExplorationEndEvent(final_result=stopaction.final_result)
```

**功能**：将 Agent 动作转换为工作流事件。

**核心逻辑**：
- 根据 action_type 分发到不同的事件创建逻辑
- godeeper 和 toolcall 会立即写入事件流
- askhuman 由框架自动写入（InputRequiredEvent 特性）
- stop 返回结束事件

**设计模式**：策略模式（根据类型选择处理策略）。

### 2.6 _process_agent_action()

```python
async def _process_agent_action(
    agent: FsExplorerAgent,
    ctx: Context[WorkflowState],
    update_directory: bool = False,
) -> WorkflowEvent:

    Process the agent's next action and return the appropriate event.

    Args:
        agent: The agent instance
        ctx: The workflow context
        update_directory: Whether to update the current directory on godeeper action

    Returns:
        The appropriate workflow event
    """
    result = await agent.take_action()

    if result is None:
```

```python
def describe_dir_content(directory: str) -> str:
    """
    Describe the contents of a directory.

    Args:
        directory: Path to the directory to describe.

    Returns:
        A formatted string describing the directory contents,
        or an error message if the directory doesn't exist.
    """
    if not os.path.exists(directory) or not os.path.isdir(directory):
        return f"No such directory: {directory}"

    children = os.listdir(directory)
    if not children:
        return f"Directory {directory} is empty"

    files = []
    directories = []

    for child in children:
        fullpath = os.path.join(directory, child)
        if os.path.isfile(fullpath):
            files.append(fullpath)
        else:
            directories.append(fullpath)

    description = f"Content of {directory}\n"
    description += "FILES:\n- " + "\n- ".join(files)

    if not directories:
        description += "\nThis folder does not have any sub-folders"
    else:
        description += "\nSUBFOLDERS:\n- " + "\n- ".join(directories)

    return description
```

**功能**：列出目录内容，分为文件和子目录。

**返回值**：格式化的目录内容字符串。

**核心逻辑**：

2. 遍历目录项，分类为文件和目录
3. 格式化输出

```python
def grep_file_content(file_path: str, pattern: str) -> str:
    """
    Search for a regex pattern in a file.

    Args:
        file_path: Path to the file to search.
        pattern: Regular expression pattern to search for.

    Returns:
        A formatted string with matches, "No matches found",
        or an error message if the file doesn't exist.
    """
    if not os.path.exists(file_path) or not os.path.isfile(file_path):
        return f"No such file: {file_path}"

    with open(file_path, "r") as f:
        content = f.read()

    regex = re.compile(pattern=pattern, flags=re.MULTILINE)
    matches = regex.findall(content)

    if matches:
        return f"MATCHES for {pattern} in {file_path}:\n\n- " + "\n- ".join(matches)
    return "No matches found"
```

**功能**：在文件中搜索正则表达式模式。

**核心逻辑**：
1. 读取整个文件内容
2. 编译正则（MULTILINE 模式）
3. 使用 findall 查找所有匹配
4. 格式化输出

```python
        return f"No such file: {file_path}"

    ext = os.path.splitext(file_path)[1].lower()
    if ext not in SUPPORTED_EXTENSIONS:
        return f"Unsupported file extension: {ext}. ..."

    try:
        full_content = _get_cached_or_parse(file_path)
        preview = full_content[:max_chars]

        total_len = len(full_content)
        if total_len > max_chars:
            preview += (
                f"\n\n[... PREVIEW TRUNCATED. Full document has {total_len:,} "
                f"characters. Use parse_file() to read the complete document ...]"
            )

        return f"=== PREVIEW of {file_path} ===\n\n{preview}"
    except Exception as e:
        return f"Error previewing {file_path}: {e}"
```

**功能**：获取文档的截断预览。

**参数**：
- `file_path`: 文档路径
- `max_chars`: 最大字符数（默认 3000）

**核心逻辑**：
1. 验证文件存在和扩展名支持
2. 调用 `_get_cached_or_parse` 获取完整内容
3. 截取前 max_chars 个字符
4. 如果截断，添加提示信息

```python
def parse_file(file_path: str) -> str:
    """
    Parse and return the complete content of a document file.

    Args:
        file_path: Path to the document file.

    Returns:
        The complete document content as markdown, or an error message.
    """
    if not os.path.exists(file_path) or not os.path.isfile(file_path):
        return f"No such file: {file_path}"

    ext = os.path.splitext(file_path)[1].lower()
    if ext not in SUPPORTED_EXTENSIONS:
        return f"Unsupported file extension: {ext}. ..."

    try:
        return _get_cached_or_parse(file_path)
    except Exception as e:
        return f"Error parsing {file_path}: {e}"
```

**功能**：解析并返回完整文档内容。

**与 preview_file 的区别**：返回完整内容，无截断。

```python
def _preview_single_file(file_path: str, preview_chars: int) -> dict:
    """
    Helper to preview a single file for parallel processing.

    Args:
        file_path: Path to the document file.
        preview_chars: Number of characters to include in preview.

        A dictionary with file info and preview content.

            "file": file_path,

            "total_chars": len(content),

    except Exception as e:
        return {
            "file": file_path,
            "filename": filename,
            "preview": "",
            "total_chars": 0,
            "status": f"error: {e}"
        }
```

**功能**：单文件预览的辅助函数，用于并行处理。

**返回值**：包含文件信息的字典。

**设计模式**：Map 函数（用于并行映射）。

### 4.12 scan_folder()

```python
def scan_folder(
    directory: str,
    max_workers: int = DEFAULT_MAX_WORKERS,
    preview_chars: int = DEFAULT_SCAN_PREVIEW_CHARS,
) -> str:
    """
    Scan all documents in a folder in parallel and return quick previews.

    Args:
        directory: Path to the folder to scan.
        max_workers: Number of parallel workers (default: 4).
        preview_chars: Characters to preview per file (default: 1500, ~1 page).

    Returns:
        A formatted summary of all documents with their previews.
    """
```

**功能**：并行扫描文件夹中的所有文档。

**参数**：
- `directory`: 文件夹路径
- `max_workers`: 并行工作线程数（默认 4）
- `preview_chars`: 每个文件的预览字符数（默认 1500）

**核心逻辑流程**：

```
1. 验证目录存在
2. 遍历目录，收集支持扩展名的文件
3. 使用 ThreadPoolExecutor 并行处理：
   - 提交 _preview_single_file 任务
   - 使用 as_completed 收集结果
4. 按文件名排序结果
5. 构建格式化的摘要报告
```

**线程池模式**：

```python
with ThreadPoolExecutor(max_workers=max_workers) as executor:
    future_to_file = {
        executor.submit(_preview_single_file, f, preview_chars): f
        for f in doc_files
    }
    for future in as_completed(future_to_file):
        results.append(future.result())
```

**输出格式**（使用 box-drawing 字符）：

```
═══════════════════════════════════════════════════════════════
  PARALLEL DOCUMENT SCAN: /path/to/folder
  Found 5 documents
═══════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────
│ [1/5] document1.pdf
│ Path: /path/to/document1.pdf
│ Status: success | Total size: 12,345 chars
├─────────────────────────────────────────────────────────────
│ (preview content, max 30 lines)
└─────────────────────────────────────────────────────────────

═══════════════════════════════════════════════════════════════
  NEXT STEPS:
  1. Assess which documents are RELEVANT to the user's query
  2. Use parse_file() for DEEP DIVE into relevant documents
  3. Watch for cross-references to other docs (may need backtracking)
═══════════════════════════════════════════════════════════════
```

**时间复杂度**：
- 文件遍历：O(n)
- 并行解析：O(n/k × parse)，k 为工作线程数
- 排序：O(n log n)

**设计模式**：
- MapReduce（映射-归约）
- 生产者-消费者（线程池）

**潜在问题**：
- `as_completed` 返回顺序不确定，需要后续排序
- 大量文件时，所有预览内容同时驻留内存

## 潜在问题和改进建议

1. **全局状态管理**：agent.py 使用模块级全局变量，建议改为依赖注入或 ContextVar
2. **缓存大小限制**：_DOCUMENT_CACHE 无大小限制，建议添加 LRU 淘汰
3. **错误处理粒度**：call_tool 捕获所有 Exception，建议分类处理
4. **线程安全**：_DOCUMENT_CACHE 非线程安全，建议加锁或使用线程安全字典
5. **scan_folder 计数**：依赖输出格式字符串计数，建议显式返回数量
6. **上下文窗口**：聊天历史无限增长，建议实现滑动窗口或摘要压缩
