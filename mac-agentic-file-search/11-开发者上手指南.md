# 开发者上手指南

> 本文档面向新加入项目的开发者，提供从环境搭建到代码贡献的完整指南。完成本文档的学习后，你应该能够独立运行 FsExplorer、理解核心架构、并进行功能开发。

---

## 1. 环境准备与安装

### 1.1 系统要求

- **操作系统**：macOS、Linux 或 Windows（推荐 macOS/Linux）
- **Python**：3.10 或更高版本
- **包管理器**：uv（推荐）或 pip
- **内存**：建议 8GB 以上（Docling 解析大文件时需要较多内存）
- **磁盘空间**：至少 500MB 可用空间（用于存储 DuckDB 索引和依赖包）

### 1.2 安装 Python 3.10+

**macOS（使用 Homebrew）：**

```bash
brew install python@3.12
```

**Linux（Ubuntu/Debian）：**

```bash
sudo apt update
sudo apt install python3.12 python3.12-venv
```

**验证安装：**

```bash
python3 --version  # 应显示 3.10 或更高版本
```

### 1.3 安装 uv 包管理器

uv 是一个极快的 Python 包管理器，由 Astral 团队开发。

```bash
# macOS/Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# 或使用 Homebrew
brew install uv

# 验证安装
uv --version
```

### 1.4 克隆仓库

```bash
git clone https://github.com/PhunkyBob/agentic-file-search.git
cd agentic-file-search
```

### 1.5 安装项目依赖

```bash
# 基础安装
uv pip install .

# 开发安装（包含测试、lint、格式化工具）
uv pip install -e ".[dev]"
```

安装完成后，验证 CLI 是否可用：

```bash
uv run explore --help
```

## 2. 配置 API Key

### 2.1 获取 Google API Key

FsExplorer 使用 Google Gemini 作为默认 LLM 提供商。

1. 访问 [Google AI Studio](https://aistudio.google.com/apikey)
2. 登录你的 Google 账号
3. 点击 **"Create API Key"**
4. 复制生成的 API Key

### 2.2 创建 .env 文件

在项目根目录创建 `.env` 文件：

```bash
# .env
GOOGLE_API_KEY="your-api-key-here"
```

> **安全提示**：`.env` 文件已被 `.gitignore` 排除，请勿将其提交到代码仓库。

### 2.3 可选：配置 Langextract

如果需要使用 langextract 进行高级元数据提取（人名、组织、金额等实体识别），需要额外配置：

```bash
# .env
GOOGLE_API_KEY="your-api-key-here"
FS_EXPLORER_LANGEXTRACT_MAX_CHARS=6000
FS_EXPLORER_LANGEXTRACT_MODEL="gemini-3-flash-preview"
```

### 2.4 可选：配置 DuckDB 路径

默认情况下，DuckDB 索引存储在 `~/.fs_explorer/index.duckdb`。可以通过环境变量自定义：

```bash
# .env
FS_EXPLORER_DB_PATH="/path/to/custom/index.duckdb"
```

## 3. 运行第一个探索任务

### 3.1 基本命令

```bash
export GOOGLE_API_KEY="your-key"
uv run explore --task "What is the purchase price?" --folder data/test_acquisition/
```

### 3.2 命令参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--task` | 要执行的查询任务（自然语言） | `"Find all contracts signed in 2024"` |
| `--folder` | 要探索的文件夹路径 | `data/test_acquisition/` |
| `--db-path` | 自定义 DuckDB 路径（可选） | `/tmp/my_index.duckdb` |
| `--verbose` | 显示详细日志（可选） | `--verbose` |

### 3.3 理解输出

运行命令后，你将看到 Rich 库渲染的终端 UI：

```
┌─────────────────────────────────────────────────────────────┐
│  FsExplorer - AI Document Search Agent                      │
├─────────────────────────────────────────────────────────────┤
│  Task: What is the purchase price?                           │
│  Folder: data/test_acquisition/                             │
├─────────────────────────────────────────────────────────────┤
│  📁 Scanning folder...                                       │
│  📄 Parsing: contract_2024.pdf                               │
│  📄 Parsing: financial_report.docx                           │
│  🔍 Analyzing content...                                     │
├─────────────────────────────────────────────────────────────┤
│  ✅ Answer:                                                  │
│  The purchase price is $2.5 million, as stated in the        │
│  acquisition agreement dated March 15, 2024.                 │
├─────────────────────────────────────────────────────────────┤
│  📎 Sources:                                                 │
│  - contract_2024.pdf (page 3, section 2.1)                   │
│  - financial_report.docx (table: Purchase Terms)             │
├─────────────────────────────────────────────────────────────┤
│  📊 Token Usage: 1,234 input / 567 output                    │
│  ⏱️  Duration: 12.3 seconds                                   │
└─────────────────────────────────────────────────────────────┘
```

**输出组成部分：**

- **面板标题**：显示任务描述和目标文件夹
- **步骤日志**：实时显示 Agent 的执行步骤（扫描、解析、分析）
- **最终答案**：Agent 生成的结构化回答
- **引用来源**：答案所依据的文档和位置
- **Token 用量**：本次探索消耗的 LLM token 数
- **执行耗时**：总运行时间

## 4. 构建索引

### 4.1 基本索引命令

```bash
uv run explore index data/test_acquisition/
```

### 4.2 高级索引选项

```bash
# 构建索引 + 计算嵌入向量 + 自动发现 Schema
uv run explore index data/test_acquisition/ --with-embeddings --discover-schema

# 指定自定义 DuckDB 路径
uv run explore index data/test_acquisition/ --db-path /tmp/my_index.duckdb

# 启用 langextract 元数据提取
uv run explore index data/test_acquisition/ --with-langextract
```

### 4.3 理解输出

```
Indexing Results:
─────────────────────────────────────────────────
Corpus ID:        corp_a1b2c3d4e5f6...
Files processed:  25
Documents indexed: 25
Chunks written:    342
Embeddings written: 342
Schema discovered: 8 fields
─────────────────────────────────────────────────
Duration: 45.2 seconds
```

**输出字段说明：**

| 字段 | 说明 |
|------|------|
| `Corpus ID` | 本次索引的唯一标识（SHA1 哈希），用于后续查询关联 |
| `Files processed` | 扫描到的文件总数 |
| `Documents indexed` | 成功索引的文档数（部分文件可能解析失败） |
| `Chunks written` | 生成的文本块总数（文档被分割为多个 chunk） |
| `Embeddings written` | 计算的嵌入向量数（仅在 `--with-embeddings` 时） |
| `Schema discovered` | 自动发现的元数据字段数量 |

## 5. 使用索引查询

### 5.1 基本查询命令

```bash
uv run explore query --task "What is the purchase price?" --folder data/test_acquisition/
```

### 5.2 高级查询选项

```bash
# 使用元数据过滤
uv run explore query --task "Find contracts" --folder data/test_acquisition/ --filter "document_type=contract"

# 指定返回结果数量
uv run explore query --task "Revenue figures" --folder data/test_acquisition/ --limit 10

# 显示详细评分
uv run explore query --task "Risk factors" --folder data/test_acquisition/ --verbose
```

### 5.3 查询与探索的区别

| 特性 | Agentic 模式（explore） | 索引模式（query） |
|------|------------------------|------------------|
| 需要预索引 | 否 | 是 |
| 执行速度 | 慢（实时解析） | 快（预计算） |
| 灵活性 | 高（动态探索） | 中（依赖索引质量） |
| Token 消耗 | 高 | 低 |
| 适用场景 | 临时查询、小文档集 | 重复查询、大文档集 |

## 6. 启动 Web UI

### 6.1 启动方式

**方式一：使用 CLI 命令**

```bash
uv run explore-ui
```

**方式二：使用 uvicorn 直接启动**

```bash
uv run uvicorn fs_explorer.server:app --host 127.0.0.1 --port 8000
```

**方式三：开发模式（自动重载）**

```bash
uv run uvicorn fs_explorer.server:app --host 127.0.0.1 --port 8000 --reload
```

### 6.2 访问 Web UI

打开浏览器访问：**http://127.0.0.1:8000**

### 6.3 界面功能说明

Web UI 提供以下功能：

- **任务输入框**：输入自然语言查询任务
- **文件夹选择**：选择要探索的目标文件夹
- **实时输出面板**：通过 WebSocket 流式显示 Agent 执行过程
- **结果展示区**：格式化显示最终答案和引用来源
- **历史记录**：查看之前的探索任务（如果启用了持久化）

### 6.4 WebSocket API

Web UI 使用 WebSocket 进行实时通信：

```javascript
const ws = new WebSocket('ws://127.0.0.1:8000/ws/explore');

ws.onopen = () => {
    ws.send(JSON.stringify({
        task: "What is the purchase price?",
        folder: "data/test_acquisition/"
    }));
};

ws.onmessage = (event) => {
    const data = JSON.parse(event.data);
    console.log(data.type, data.content);
};
```

## 12. 添加新工具指南

### 12.1 详细步骤

#### Step 1: 实现工具函数

在 `fs.py`（文件系统操作）或 `agent.py`（索引操作）中实现函数：

```python
# fs.py
def search_by_regex(pattern: str, folder: str) -> str:
    """Search documents using regex pattern."""
    import re
    results = []
    for file_path in Path(folder).rglob('*'):
        if file_path.suffix in SUPPORTED_EXTENSIONS:
            content = parse_document(str(file_path))
            matches = re.findall(pattern, content)
            if matches:
                results.append({
                    'file': str(file_path),
                    'matches': matches[:10]  # 限制返回数量
                })
    return json.dumps(results, ensure_ascii=False)
```

#### Step 2: 添加到 TOOLS 字典

```python
# agent.py
TOOLS = {
    ...,
    "search_by_regex": search_by_regex,
}
```

#### Step 3: 添加到 Tools TypeAlias

```python
# models.py
Tools = Literal[
    ...,
    "search_by_regex",
]
```

#### Step 4: 更新 SYSTEM_PROMPT

```python
# agent.py
SYSTEM_PROMPT = """
...
Available tools:
- search_by_regex: Search documents using a regular expression pattern. 
  Parameters: pattern (str), folder (str)
...
"""
```

#### Step 5: 更新 main.py 的图标和描述

```python
# main.py
TOOL_ICONS = {
    ...,
    "search_by_regex": "🔍",
}

PHASE_DESCRIPTIONS = {
    ...,
    "search_by_regex": "Searching with regex pattern",
}
```

#### Step 6: 编写测试

```python
# tests/test_fs.py
def test_search_by_regex():
    result = search_by_regex(r"\$\d+,\d{3}", "data/test_acquisition/")
    data = json.loads(result)
    assert len(data) > 0
    assert "file" in data[0]
    assert "matches" in data[0]
```

### 12.2 工具设计原则

- **单一职责**：每个工具只做一件事
- **返回字符串**：工具函数必须返回 `str` 类型（会被发送给 LLM）
- **错误处理**：工具内部应捕获异常并返回友好的错误信息
- **参数简洁**：避免过多参数，复杂输入可考虑使用 JSON 字符串

## 14. 常见问题排查

### 14.1 GOOGLE_API_KEY 未设置

**症状**：

```
Error: GOOGLE_API_KEY environment variable is not set
```

**解决方案**：

```bash
# 检查环境变量
echo $GOOGLE_API_KEY

# 如果为空，设置环境变量
export GOOGLE_API_KEY="your-key"

# 或在 .env 文件中添加
echo 'GOOGLE_API_KEY="your-key"' >> .env
```

### 14.2 DuckDB 文件锁定

**症状**：

```
Error: Could not lock file "/Users/.../index.duckdb"
```

**原因**：另一个进程正在使用 DuckDB 文件（DuckDB 不支持多写）。

**解决方案**：

```bash
# 查找占用文件的进程
lsof ~/.fs_explorer/index.duckdb

# 终止占用进程
kill -9 <PID>

# 或删除锁文件（谨慎操作）
rm ~/.fs_explorer/index.duckdb.lock
```

### 14.3 Docling 解析失败

**症状**：

```
Warning: Failed to parse document.pdf: ...
```

**可能原因**：

- 文件损坏或加密
- 文件过大导致内存不足
- 特殊编码或字体问题

**解决方案**：

```bash
# 检查文件是否可读
file document.pdf

# 尝试用其他工具打开
open document.pdf

# 检查文件大小
ls -lh document.pdf
```

### 14.4 超时问题

**症状**：探索任务执行时间过长或超时。

**解决方案**：

```bash
# 限制扫描的文件数量
uv run explore --task "..." --folder data/test_acquisition/ --max-files 10

# 使用索引模式（更快）
uv run explore index data/test_acquisition/
uv run explore query --task "..." --folder data/test_acquisition/
```

### 14.5 测试失败

**症状**：`pytest` 报告测试失败。

**常见原因**：

- 全局状态未清理：确保测试中调用了 `reset_agent()`
- Mock 未正确配置：检查 `MockGenAIClient` 的返回值
- 文件路径问题：使用绝对路径或 `Path(__file__).parent` 定位测试文件

```python
# 正确的测试写法
def test_something():
    reset_agent()  # 清理全局状态
    agent = get_agent()
    agent._client = MockGenAIClient()
    # ... 执行测试 ...
    reset_agent()  # 清理
```
